# 动作生产规格与待解决方案

> 给模型侧（GPT）的交接文档。目标：在 V8 绑定上产出「可被 LLM 选择、可分层叠加」的动作库。
> 相关设计：[DESIGN.md](./DESIGN.md) v0.4 与第 8 节「分层动画」。
> 日期：2026-10-24

---

## 1. 背景

运行端（DeepSeek）已经放弃“实时求解骨骼”的路线，改为：

**预生成动画片段 → LLM 根据情境选择片段 → 运行时播放与分层混合。**

现在的问题是：V8 绑定上**没有任何身体动作**（只有一条摆尾）。

此前在 V4 绑定上做的四段动作（`01_Idle` / `02_Nod` / `03_Look` / `04_Greet`）**不能直接用于 V8**：
两套绑定的静止姿态不同，动画片段存的是相对静止姿态的局部旋转，直接套会扭曲甚至炸开。
跨骨架重定向已经尝试并失败，因此改为**在 V8 绑定上直接制作**。

---

## 2. 用户刚提出的调整：分层动画

要求手、脚、尾巴、脸可以各自独立播放，例如：

- 走路的同时挥手
- 说话/待机时眨眼，与身体动作无关
- 摆尾不受上身动作影响

分层表：

| 层 | 覆盖骨骼 | 片段 |
|---|---|---|
| base | 全身（含手臂摆动） | idle_stand / walk / run / sit_* |
| upper | 肩、手臂、手、头、颈 | greet / notice / nod / look_* / think |
| tail | `WhaleTail_01..06` | tail_idle / tail_swish |
| face | 形态键（morph） | blink / 表情 |
| gaze | `head.x`（限幅 ±15°） | 程序化，不需要交付 |

**实现原理**：three.js 的 `AnimationMixer` 只影响片段里有轨道的骨骼，
所以只要按层切分轨道，天然就是 mask，不需要额外的遮罩系统。

## 3. 绑定与命名基线

- 文件：`tail_v8/Character_WhaleTail_Attached_v8.blend`
- 骨架：`rig`，376 骨，95 根 deform
- 身体网格：`SK_Character_Master`；尾巴网格：`WhaleTail`
- 单位：米，30 fps，角色朝 +Z（glTF 空间）
- 尾巴骨：`WhaleTail_01` … `WhaleTail_06`（父级 `WhaleTail_Root`）
- 头颈：`head.x`、`neck.x`、`c_head.x`、`c_neck.x`、`subneck_twist_1.x`
- 手臂（变形骨）：`shoulder.l/r`、`arm.l/r`、`forearm.l/r`、`hand.l/r`，
  另有 `arm_twist.*`、`forearm_twist.*`、`*_stretch.*` 等辅助骨由约束驱动
- 躯干：`spine_01.x` … `spine_05.x` 及对应 `c_spine_*`

## 4. 待解决方案（需要模型侧答复或共同确认）

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| S1 | **移动片段用根运动还是原地？** | 决定移动控制器与滑步处理 | 推荐原地 + 运行时速度匹配；若用根运动，请说明提取方式 |
| S2 | **upper 层与 base 层在手臂上冲突** | 一边走一边挥手时，base 的摆臂会和挥手打架 | 推荐 upper 片段只含上半身骨，且运行时让 upper 完全覆盖手臂；base 继续驱动腿 |
| S3 | **片段的首尾姿态** | 淡入淡出是否自然 | 每段首尾尽量接近 `idle_stand` 的同一姿态，并在交付说明里注明 |
| S4 | **导出时是否会烘焙全部骨骼** | 若导出器给每段都写全身轨道，分层失效 | 导出必须**只包含该层骨骼的动画轨道**，或提供可裁剪的中间文件 |
| S5 | **脸部形态键损坏** | blink / 表情无法启用 | 需要单独修复；修复前 face 层保持禁用 |
| S6 | **领结权重缺陷** | 摇头、抬手时领结剪切 | 建议与动作同批修复，或在验收中说明可接受范围 |
| S7 | **动作的进入条件与冷却** | 运行时状态机需要元数据 | 每段交付 `loop`、`duration`、`interruptible`、`cooldown`、`allowedStates` |
| S8 | **LLM 是否可调速度/幅度** | 影响接口设计 | 建议 speed ∈ [0.75, 1.25]，只对 locomotion 生效 |
| S9 | **尾巴是否独立片段** | 决定 walk/idle 里是否含尾巴 | 推荐独立成 tail 层片段，idle/walk 不写尾骨 |
| S10 | **打断与过渡时长** | 影响观感 | 建议 0.2–0.3s 交叉淡出，一次性动作播完回 idle |

## 5. 动作清单与规格

### P0（先做这五段，能跑通完整演示）

| id | 层 | 循环 | 时长 | 轨道范围 | 说明 |
|---|---|---|---|---|---|
| `idle_stand` | base | 是 | 4.0s | 全身（不含尾骨） | 呼吸、重心微动、头部轻微晃动 |
| `walk` | base | 是 | ~1.2s/循环 | 全身（不含尾骨） | 原地走，步频稳定 |
| `run` | base | 是 | ~0.8s/循环 | 全身（不含尾骨） | 原地跑 |
| `greet` | upper | 否 | 2.5–3.0s | 肩、臂、手、头 | 抬手挥手，结束时回到接近 idle 的姿态 |
| `notice` | upper | 否 | 1.5s | 头、颈、肩 | 被点击的转头反应 |

### P1

| id | 层 | 循环 | 时长 | 说明 |
|---|---|---|---|---|
| `nod` | upper | 否 | 1.5s | 点头 |
| `look_left` / `look_right` | upper | 否 | 2.0s | 左右看，头颈分配约 7:3 |
| `think` | upper | 是 | 3.0s | 抬头、轻微侧倾、慢速 |
| `tail_idle` | tail | 是 | 3.0s | 小幅摆尾 |
| `tail_swish` | tail | 是 | 2.0s | 大幅摆尾 |

### P2

- `blink`（face，依赖 S5）
- `sit_down` / `sit_idle` / `stand_up`（base）

## 6. 轨道切分约定（最关键）

每段动作在 Blender 里**只对所属层的骨骼打关键帧**：

| 层 | 允许出现的骨骼 |
|---|---|
| base | 全身，但**不含** `WhaleTail_*` |
| upper | `shoulder.*`、`arm.*`、`forearm.*`、`hand.*`、`neck.x`、`head.x`、`c_shoulder.*`、`c_arm_fk.*`、`c_forearm_fk.*`、`c_head.x`、`c_neck.x` |
| tail | 仅 `WhaleTail_01..06`（可含 `WhaleTail_Root`） |
| face | 仅 morph target，不含骨骼 |

**验收方式**：导出后检查 GLB 的 animation channel 覆盖的节点集合，
必须落在上表范围内。若出现整身 376 个节点，说明导出器做了全骨烘焙，分层会失效。

---

## 7. 技术约定

- 帧率 30，单位米，Y-up（导出时转换）
- 片段命名与上表 id 完全一致
- 一次性动作首尾姿态尽量接近 `idle_stand`，便于 0.25s 淡出
- 每个片段单独交付：GLB（或 .blend + 导出脚本）+ 预览 GIF + 轨道清单
- 版本字段：`assetVersion`、`clipVersion`、源文件 SHA-256

---

## 8. 验收标准

1. 在 V8 上播放不扭曲、不炸开（正面 / 侧面 / 背面三角色各检查一次）
2. 轨道集合符合第 6 节的分层约定
3. `idle → 片段 → idle` 的淡入淡出无明显跳变
4. 循环片段首尾无缝
5. 移动片段在 0.75–1.25 倍速下脚步无明显滑动（或说明根运动方案）
