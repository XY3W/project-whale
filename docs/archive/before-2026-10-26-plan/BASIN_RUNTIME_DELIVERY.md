# 钢盆 v2 运行时接入交付报告

2026-10-25 · DeepSeek 实现 · 对应交付包 `assets/basin-actions-v2/` 与 `docs/BASIN_ANIMATION_V2_DELIVERY.md`

## 先更正上一轮的错误结论

上一轮记录的“手部挂接不生效”是**误判**。用 Node 直接复算 `catalog` 的挂接矩阵后确认：

```text
pickup_basin @ 1.05s:  hand.matrixWorld × bindings.hand = (-0.546, 0.1337, 0.2101)
catalog.pickupReference.position               = (-0.546, 0.1337, 0.2101)
差值 = 0.0000 m
```

抓取事件时刻盆本来就应该停在原处——动画把手移到盆沿，不是把盆移到手边。挂接矩阵由作者按“抓取帧对齐”导出，所以 `grasp` 瞬间位置不变才是正确行为。之前的调试把正确现象当成了 bug。

真正的证据链是抓取之后：持盆姿态下盆的世界坐标为 `(-0.537, 0.415, 0.314)`，与 `hold_basin` 首帧、`unwear_basin` 的 `hand_catch` 帧完全一致；戴上后为 `(0.001, 0.914, -0.068)`，与头部挂点离线计算一致。

### 状态机

`resting → reserved(拾取开始) → held(grasp) → transferring(hand_release_to_transfer) → worn(head_attach) → transferring(head_release_to_transfer) → held(hand_catch) → flying(release) → resting(落地静止)`

- 取消按“动作开始前状态”回滚；`reserved` 回 `resting` 并恢复原世界姿态，不会凭空复制一只盆。
- `held/worn` 期间每帧用实时骨骼世界矩阵重算，角色走动、转身、转头时盆跟随。
- `transferring` 期间只由 `prop_motion` 曲线驱动，`wearMorph` 同步；`head_attach` 后强制 1，取下后回 0。
- 戴头时 `throw` 被状态机拒绝（必须先 `unwear`），避免盆从头顶飞出。

### 事件时序

播放器按 `previousTime < eventTime ≤ currentTime` 触发，并把本帧拆成“先求值到事件时刻 → 更新骨骼世界矩阵 → 执行挂接/脱手 → 再吃掉剩余时间”。60 fps 与 4 fps 下事件时刻一致（实测 `grasp@1.050s`、`hand_release_to_transfer@0.700s`、`head_attach@1.950s`、`head_release_to_transfer@0.650s`、`hand_catch@2.000s`、`release@0.880s`）。

### 拾取站位

盆在角色根局部的偏移固定，所以站位必须落在“以盆为圆心、半径 0.585 m”的圆上；步行距离只能取 `0.09 + 0.18n`。两个圆的交点给出精确站位，因此不存在“距离够近就凑合抓”的容差：

- `walk_to_basin` 实测：径向误差 `0.3 mm`、朝向误差 `0.43°`，`pickup` 前置条件 `≤2 cm / ≤2°`。
- 超过一段步行可即时，先朝盆走 1.89 m 再重算，最多 10 段。
- `pickup` 本身不做任何导航；未对准直接返回 `NOT_ALIGNED` 并带上实际误差。

### 落地抽搐的根因与修正

现象：盆落地后长时间“抽搐”，线速度一直在 5 cm/s 上下、角速度 0.2 rad/s 左右，永远进不了静止。

根因不在状态机，而在碰撞体：**261 点的凸包落在平面上时接触流形持续抖动**。盆是薄壁碗形，凸包把内壁也算成实体，贴地后接触点不断在几条边之间跳，求解器每帧给出方向相反的小修正，视觉上就是抽搐。

修正分三层：

1. **碰撞体换成外接圆柱**（半径 0.371 m、半高 0.134 m，中心对齐网格包围盒）。圆柱的平面/直线接触稳定，实测静止耗时从“永不静止（被 6 秒兜底强停）”降到 **1.37 秒**，且静止时 `v=0, w=0`。外接尺寸保证任何姿态都不穿地。
2. **阻尼与摩擦**：线阻尼 0.12、角阻尼 0.9、弹性 0.15、摩擦 0.9，避免像轮子一样无限滚动。
3. **静止判定看位移而不只是速度**：速度阈值（0.06 m/s / 0.9 rad/s）之外，再看最近 0.4 秒的实际位移（<0.4 mm）与转角（<0.002 rad）；贴地缓慢打转也会被判为静止。另有“贴地超过 6 秒强制静止”的兜底。

生产浏览器实测 119 帧轨迹：飞行 64 帧 → 静止 38 帧，**静止后位移抖动 0 次**。

### 空气墙

场地是 ±4 m，物理世界在四面各加一道厚 0.5 m、高 3 m 的固定挡板（再往外半米）。投掷方向再偏、速度再大，盆也留在场内；Node 测试用 9 m/s 朝 +X、以及 (7, 3, 7) 斜向高速验证，最终 |x|、|z| 都小于 4.6。

### 重置与自动扶正

- **重置**：主页面左上角“重置盆”按钮（`/basin.html` 里的 `center` 按钮同样效果）把盆直接放回场地中心 `(0, 0.134, 0)`、正放、静止，并打断正在播放的互动，物理刚体同时移除。
- **拾取自动扶正**：`pickup` 时如果盆是侧躺或倒扣，先做 0.45 秒平滑插值，把它摆到“当前站位对应的标准姿态”，再播拾取。实测把一个 92.7° 侧躺的盆扶正并成功拾取。扶正只允许小幅摆正：水平位移超过 0.35 m 就拒绝并返回 `NOT_ALIGNED`，仍然必须先走近。`available` 因此改为“静止即可拾取”，姿态单独由 `upright` 表示。

### 投掷与物理

0.88 s 的 `release` 用当时的实际手部世界姿态解绑，按 `yaw_deg / elevation_deg / speed_mps` 初始化刚体（自转固定 180°/s），之后盆的位置与旋转只来自物理系统。片段结束不写回 `flying`：落地就可能已经是 `resting`，执行器两种状态都接受。落地静止判定为线速度 < 0.03 m/s、角速度 < 0.25 rad/s 持续 0.4 s。

## 尚未完成 / 能力边界

1. **拾取只验证平地**。斜坡、以及正在移动（未静止）的盆仍会返回 `BASIN_STATE_MISMATCH`；姿态问题已由自动扶正覆盖。
2. **投掷后可以再拾取，但会“吸”到手里**。落地侧躺时靠扶正把小幅度位移的盆摆到抓取点；位移超过 0.35 m 会被拒绝，这是资产缺口的折中，不是真正的躺姿拾取动画。
3. **投掷方向受基础动作限制**。大幅侧向/向后投掷没有专门身体动作，只有基础朝前出手；执行器只校验参数范围，不校验“这个方向好不好看”。
4. **物理为单一圆柱体**。碰撞体是外接圆柱而不是薄壁碗形，盆不会与其它物体嵌套，也不会被压住；场景里目前只有地面和四面空气墙。
5. **长距离接近是分段宏**。`walk_to_basin` 内部最多 10 段 turn/walk；被墙或边界挡住时返回 `OUT_OF_BOUNDS`，不做绕障。
6. **动画时长与墙钟无关**。低帧率机器上 3.1 s 片段可能跑 20 s 以上，执行器的超时只做卡死兜底（60 s），真实完成判定来自片段事件与结束回调。
7. 内存确认/删除 UI、±180° 与实际动画的浏览器复核、完整任务经 UI 的真实模型闭环仍未做。
