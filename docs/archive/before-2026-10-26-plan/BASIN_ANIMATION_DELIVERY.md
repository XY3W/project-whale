## 动作与事件

时间单位为秒，从 clip 的 `time=0` 开始。源 Blender 第 1 帧对应 clip 的 0 秒；不要混淆帧编号与时间。

| 动作 | 时长 | 物品事件 | 结束姿势 |
| --- | --- | --- | --- |
| `pickup_basin` | 3.10 | 1.05：`grasp`，resting → held | 右手持盆 |
| `hold_basin` | 2.00，循环 | 无 | 右手持盆 |
| `throw_basin` | 2.30 | 0.88：`release`，held → flying，交给物理 | 空手站立 |
| `wear_basin` | 3.00 | 0.70：`hand_release_to_transfer`；1.95：`head_attach` | 戴盆站立 |
| `unwear_basin` | 3.00 | 0.65：`head_release_to_transfer`；2.00：`hand_catch` | 右手持盆 |

戴上流程是 held → transferring → worn；取下是 worn → transferring → held。`transferring` 是执行器内部、由动画独占控制的状态，不需要给 LLM 增加一个“自由飞行”指令。它与投掷的 `flying` 不同，不能接入重力和碰撞反弹。

事件按动作实例去重。当 `previousTime < eventTime <= currentTime` 时触发，掉帧跨过事件也必须执行一次；不能用浮点时间相等来判断。先把动画求值到事件时刻，更新骨骼世界矩阵，完成脱手/挂接，再继续推进本帧剩余时间。所有者、任务代际、租约和事件账本由现有运行框架校验。

投掷片段结束时不强制写回 `flying`：盆可能早已落地，必须保留物理系统最新权威状态。

## 加载、分层与挂接

- 角色仍需已有的多权重支持。新 GLB 保留 `JOINTS_0..3 / WEIGHTS_0..3`，不要只读取前四个影响或换成未经验证的四权重副本。
- 四个一次性互动片段控制身体骨骼，排除了六根独立尾骨；期间停止漫游与其他身体动作，避免 attention、gesture 和 walk 混合覆盖。
- `hold_basin` 只包含 8 根右臂骨轨道，清单见 `tracks.json`。以绝对姿势覆盖对应右臂轨道，其他骨骼由 idle 或 walk 提供；不要把它作为 additive 动作，也不要让其他动作以同权重再次控制右手。
- 身体动画不推进角色世界位置；拾取下蹲发生在骨架内部。路径移动由 locomotion 完成。
- 建议入场/退出混合 0.15 秒；事件时刻必须保证本动作已经完全控制相应骨骼。持盆时持续保留 `hold_basin`，不要在拾取结束后恢复空手右臂。
- 骨骼、衣物和头发已经烘焙，不要求浏览器运行 Blender 约束系统。尾巴可保持现有独立尾巴层；叠加后的持盆走路、转向、尾巴表现仍须在浏览器验收。

`catalog.bindings.hand/head.matrixColumnMajor` 是 glTF 骨局部挂接矩阵。用单位缩放的容器包住整个盆 glTF scene；不附加额外的轴向转换或缩放。

```text
盆的世界矩阵 = 实际挂点骨骼.matrixWorld × 对应挂接矩阵
```

如果盆直接成为骨骼子节点，将挂接矩阵设为盆容器的 local matrix。若放在公共物品容器下，则用该父容器的逆世界矩阵换算成本地矩阵。不要在旧父节点变换上重复相乘。矩阵来自本次实际导出骨架，不能用编辑器中的欧拉角猜测替代。

`prop_motion` 中的坐标为“角色根局部坐标”，glTF 的 +Y 向上、+Z 向前，单位米，四元数顺序为 xyzw。位置线性插值、旋转最短路径 slerp。只有转移期间由曲线驱动盆；held/worn 期间以实时骨挂点为准，保证角色走动和转头时正确跟随。

## 拾取：先走到正确位置

这版拾取动画验证的是平地、盆口朝上、已经静止的盆。盆位于角色右前侧，角色蹲下抓盆沿后抬起，再把盆转成侧持姿势。

标准位置在 `catalog.pickupReference`：盆原点相对角色根约为 **(-0.54603, 0.13366, +0.21009) 米**。负 X 是角色右侧；盆原点不在盆底，因此 Y 不能误设为 0。

1. LLM 决定是否拾取、选择物品并安排移动；执行器检查目标存在、静止、未被占用及可达。
2. 根据目标盆位置与选择的角色朝向，计算站位：水平面上 `角色位置 = 盆位置 - yawRotation × pickupReference.position`；角色高度由地面确定。
3. 走到该站位并完成转向后，重新验证物品位置和姿态，才能播放拾取。不要仅凭“距离小于某个大阈值”就允许抓取。
4. 1.05 秒之前盆保持世界位置不动，不允许为了匹配动画把盆吸附或传送到脚边。1.05 秒检查实际手部抓点是否吻合后才提交 held 事件。
5. 若物品被撞开、被抢走或姿态不适用，应拒绝抓取并返回真实失败原因，不能只播放动画后报告成功。

当前验证覆盖标准对齐姿态，不声称任意偏移都可直接抓取。侧翻、倒扣、斜坡以及空中接物需要补充动画或受约束的手部 IK。首版应将不支持的物品姿态反馈给 LLM，不能自动扶正或远距离吸取。若首版业务要求“投掷后无论如何落地都能再捡起”，这仍是明确的后续资产/交互缺口。

## 戴上、取下与头发修正

戴上与取下都是轻巧卡通抛接。手不需要够到头顶盆沿，也不改变身体比例。转移期间禁止其他拾取、投掷、重复戴盆及相冲突的身体动作。

新角色 GLB 内包含 `Basin_v2_Wear_Crown_Tuck`，只用于盆覆盖区域的头顶收拢；沿 `prop_motion` 的 `wearMorph` 驱动。挂到头顶后持续保持 1，取下后恢复 0。不要在 clip 结束时一律清零，否则头顶头发会重新穿盆。该形态键独立于骨骼动画，必须由运行时显式设置。原来禁用的表情/眨眼形态键没有在本次恢复。

取消处理需尊重提交点：转移开始前可以退回原 held/worn；转移开始后正常取消应延迟至安全挂接点，再结束动作。租约丢失或页面关闭时由权威状态机记录和对账，未完成转移不能报告成功，也不能为恢复外观凭空复制一只盆。

## 投掷与物理接管

投掷从右手侧持姿势开始，包含小幅蓄力、向前出手和回收手臂。0.88 秒取得盆的实际世界位置与旋转，解除挂接，启用动态刚体，再由运行时根据 LLM 指定且经过验证的方向、速度与角速度初始化物理运动。

本包不包含碰撞反弹算法，也没有把飞行轨迹烘进正式运行数据：`prop_motion.throw_basin` 截止到脱手事件。不能继续播放作者示意曲线去覆盖物理刚体。GIF 在脱手时隐藏盆，明确展示控制权移交，只用于看身体动作，不代表物理预览。

戴在头上的盆先执行 `unwear_basin`，再执行投掷。当前身体动画是朝前出手的基础动作；大幅侧向/向后投掷应先显式转身，或者补充经过验证的动作适配，不能任意拧腕匹配全部速度方向。现有方案中的参数范围仍需要物理沙盒验收，资产制作不等于这些范围已全部验证。

## 建议接入验收顺序

1. 独立沙盒加载新角色和盆，确认 21 段片段、83 骨、多权重与头顶形态键可用。
2. 固定标准站位验证：地面 → 拾取 → 持盆 → 戴上 → 取下 → 投掷；检查事件只执行一次、同一只盆保持唯一身份。
3. 验证物理接管、反弹衰减和最终静止，再检查哪些落地姿态可被当前拾取能力接受。
4. 验证持盆走路、转头、状态切换与动作打断，没有混合导致的盆/身体穿插。
5. 验证超范围、目标移动、取消、掉帧、页面刷新、执行权切换和失败反馈，再接入 LLM 自主调用。拾取、戴上、取下、投掷及其前置条件都要出现在能力注册表和场地快照里。

这些步骤由 DeepSeek 接入时执行；本次没有改服务器代码，也没有把尚未验证的运行行为标成完成。
