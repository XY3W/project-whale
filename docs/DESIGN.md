# Project Whale · 设计

> v0.7 · 2026-10-24
> 方向：预生成动画 + LLM 选择 + 分层叠加。

## 0. 目标与技术方案

### 0.1 要做什么

一个 DeepSeek 鲸鱼娘 3D 桌宠。它待在一个空场里，可以自由观察、点击移动、说话；
**由 DeepSeek 决定“现在做什么”**——从一套精心制作的动画里挑一个，而不是实时生成动作。

核心价值不在“模型生成动作”，而在：

- **动作质量由美术保证**（预生成片段）
- **性格来自选择**：选什么、什么时候选、说什么
- **可分层**：走路时能挥手，说话时尾巴自己在摆

### 0.2 一期范围

| 做 | 不做 |
|---|---|
| 单个角色（V8 绑定） | 换装、多角色 |
| 一个空场 + 自由相机 | 家具、道具、物理互动 |
| 8–10 个动作片段 | 程序化骨骼控制、IK 抓取 |
| 分层播放（base/upper/tail） | face 层（等形态键修复） |
| 点击移动 + 点击反应 | 寻路避障 |
| 气泡说话（文本） | TTS / 语音输入 |
| 规则导演 → DeepSeek API | 多轮长记忆 |
| homeserver 内网部署 | 公网、多端同步 |

### 0.3 技术方案

```
资产    Blender（V8 绑定）→ 按层切分轨道的 GLB 片段
运行时  three.js + AnimationMixer
        ├─ catalog   动作目录（id/层/循环/时长/可打断/冷却）
        ├─ player    分层权重、交叉淡出
        ├─ state     idle / moving / acting
        └─ locomotion 位置朝向、速度匹配
大脑    规则导演（先）→ DeepSeek 工具调用（后）
        list_actions / play / move_to / say / stop
部署    Docker on homeserver 192.168.0.100:8090（内网）
```

关键约定：

- 按烘焙后的节点与属性划分轨道所有权；base 拆为下身与上身同步播放，upper 通过上身通道权重覆盖基础上身，不能依赖 AnimationMixer 自动覆盖
- 移动必须用 `locomotion` 片段；执行器拒绝类型不符
- LLM 只输出动作 id 与少量参数，不接触骨骼

### 0.4 资产依赖

1. V8 动作库（规格见 [ANIMATION_SPEC.md](./ANIMATION_SPEC.md)）
2. 脸部形态键修复（阻塞眨眼与表情）
3. 领结权重修复及头颈、抬手姿态验证（V9 已通过交付动作范围验证，详见 ANIMATION_DELIVERY_V9.md）

### 0.5 可选：VRM

VRM 是**资产规范**，不是动画方案。它能让动作库跨模型复用、自带表情与弹簧骨，
但动画本身、分层逻辑仍由我们实现。建议运行时稳定后再决定是否迁移；
迁移主要动资产层，不推翻现有运行时。

### 0.6 已确认（2026-10-24）

1. **大脑用 DeepSeek API**，Key 只放服务端，浏览器不接触
2. **一期只出气泡**，不接 TTS
3. **先做网页版**，Tauri 桌面窗后置
4. **用户确认新方向：预制动作库为主，运行时分层播放，LLM 选择动作**，替代此前实时语义参数驱动骨骼方案
5. 一期移动仍限平地慢走；跑步、坐下留作后续扩展
6. 观察模式禁止自动转身，停止拖动相机不会自动退出观察模式

## 1. 方向

角色不再由代码逐帧控制骨骼，而是：

**LLM 根据情境选择一个动画片段 → 运行时播放并分层混合。**

这样做的好处：动作质量由美术保证，LLM 只做它擅长的离散选择，
减少自由骨骼参数造成的失控；分层混合、过渡和移动仍须验证扭曲、滑步与穿模。

## 2. 架构

```
浏览器
├─ catalog    动画目录（id、层、循环、时长、可打断、冷却）
├─ player     AnimationMixer + 分层权重 + 交叉淡出
├─ state      idle / moving / acting
├─ locomotion 位置与朝向、速度匹配
└─ input      点击、拖动、相机

homeserver（后续）
└─ brain      规则导演 → 未来 DeepSeek；记忆与情绪
```

## 3. 分层

| 层 | 覆盖 | 片段 |
|---|---|---|
| base | 全身（不含尾巴） | idle_stand / walk（run / sit_* 后续） |
| upper | 肩臂手头颈 | greet / notice / nod / look_* / think |
| tail | `WhaleTail_01..06` | tail_idle / tail_swish |
| face | 形态键 | blink / 表情（依赖修复） |
| gaze | 暂不直接修改头骨 | 待领结与头颈验证通过后另定；当前使用预制 look 动作 |

轨道切分只限制影响范围，不提供重叠轨道优先级。基础上身与 upper 的有效权重需互补；基础下身继续播放。第一版 upper 使用完整上身姿态，包含依赖的辅助变形骨。具体轨道清单由烘焙依赖生成，不能只列控制骨名称。

## 4. 状态机

状态采用独立通道，允许 moving 与 upper 动作同时成立：

- 移动通道：idle / moving；手势通道：none / playing / fading；尾巴独立循环。
- upper 播放时淡出基础上身；结束后恢复当前 base 上身（走路中恢复摆臂），不重置下身或移动状态。
- 交叉淡出以 0.2–0.3s 为起点，逐片段验证。循环的相位、一次性动作的打断窗口记录在目录中。
- 观察是独立输入模式：相机拖动进入观察，松手仍保持；观察期间禁止导演/LLM 自动移动或转身。
- Esc（文本输入未聚焦时）或“恢复互动”按钮明确退出；用户显式移动/转身命令也可退出。点击角色可触发 notice，但不退出观察。退出本身不触发朝向相机。

## 5. LLM 接口

```
list_actions()                  → 可用动作 + 描述 + 约束
play(action_id, params?)        → 播放
move_to(target, style: walk)→ 选 locomotion + 移动
say(text)                       → 气泡
stop()                          → 移动通道受控停止并回 idle；其他通道按打断策略处理
```

移动必须走 `locomotion` 类片段；选错类型执行器拒绝。
