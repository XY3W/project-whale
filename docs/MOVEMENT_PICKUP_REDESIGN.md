# 移动与拾取改造：已确认的设计

状态：本地实现与验证中。模型接口为坐标式 move_to；旧步长接口保留为兼容内部调用，不出现在新能力说明中。

## 决策与接口

模型决定目标坐标、行为和需要时的路线；执行器负责转向、步态、位移、收步、到位和报告。模型只通过 `move_to` 指定世界坐标目标（x、y、z），不以物品、棋子或格子 ID 作为移动目标。当前只允许地面高度；未来支持高低差和攀爬时再启用其他高度。目标在服务端限制最大范围 ±5.45 米，并由客户端按当前场地范围复核；地面模式只接受 y=0。默认到位误差 0.1 米。朝向和路线选择可作为可选参数，接口实现前应确定其具体契约。

场景状态提供物品、棋盘等位置及可交互范围；可提供已算好的候选站位坐标供模型选择。候选站位不是 move_to 的对象目标，也不自动触发拾取或其他互动。路线查询未来应依据真实场景返回可用路线及走路、攀爬等能力，模型可选择路线；路径失效时执行器停止并返回结果。第一版不宣称已经具备三维寻路或攀爬。

现有跑步动画在产品语义中改为「走路」，用于一般移动、漫游及游戏移动；现有走路动画改为「慢走」，用于靠近终点、短距离或精细站位。抱棋允许走路，继续独立叠加双手托棋姿态。执行器自动选择走路和慢走，不要求模型指定。移动接口接受连续坐标，默认到位误差 0.1 米；内部仍将距离分解为经过验证的素材片段，而非真正连续的步态生成。长距离可在一个较快步态中连续循环，再用慢走或短步补足。位移与动画时钟同步，不强行插值角色位置；因此接近目标时仍可能出现一次收步和短步，后续仍可优化衔接。

## 拾取

所有可拾取物品：角色进入该物品的拾取半径后即可拾取，不需要精确朝向、精确参考站位或支持某个落地姿态。成功时直接将物品挂到对应空闲手，无踢勺、弯腰等拾取动作。象棋搬棋在走近后也直接将棋子挂到双手；不能暗中移动角色；范围外报告距离和范围，由模型决定移动和拾取。仍检查物品存在、可用、未被占用、槽位可用等状态。目前两种物品均按角色根位置到物品原点的三维距离 ≤0.8 米判定，并向模型提供距离阈值和物品三维坐标；未来高度不同的物品需避免仅用水平距离造成隔层拾取。不得依赖自动扶正或参考站位。

## 改造清单

- `server/capabilities.mjs`、工具 schema、协议、校验、提示词与错误反馈：统一坐标式接口，移除对模型的固定距离、朝向与对齐要求；旧接口是否保留内部兼容需核查历史计划和恢复逻辑。
- `src/character/LayeredMotionPlayer.ts`、`src/behavior/locomotion.ts`、`src/main.ts`：实现连续目标位移、选速和移动取消；避免通过直接修改世界坐标造成滑步或穿越边界。检查所有移动调用共享同一执行器。
- `src/behavior/roam.ts` 与随机漫游、扫雷、五子棋、象棋流程：迁移到统一移动；对游戏落点、授权、物品持有和取消中断保持既有语义。
- `src/prop/PropItem.ts`、`ActionExecutor.ts` 和物品快照：改为同一拾取范围判定及原子瞬时挂手；清除精确对齐、姿态变体、自动扶正作为拾取前置要求；保留模型和素材原文件。
- 测试：覆盖任意距离与容差、短距离、边界、步态衔接、速度档位、打断、抱棋及持物组合、各游戏站位、拾取半径内外和物品占用、状态恢复、协议与提示词。真实模型视觉验收与自动化检查分别报告。
