# 象棋接近与抱棋跑动修复

2026-10-31。用户确认空手接近、抱棋搬运两段都太慢，并明确“抱棋阶段不用禁跑”。这条决定优先于历史代码中的抱棋禁跑限制。

## 原因

服务器已部署包含 DeepSeek `78954db` 的版本，不是其修改被覆盖。原修复只让部分空手目标路径允许跑动，仍有三处限制：

- 分段器要求剩余距离大于 1.2m，还固定留下至少 0.6m 慢走尾段；慢走速度约 0.1125m/s，仅尾段就至少约 5.3 秒。
- 象棋搬棋的后半段显式传入 `allowRun=false`。
- 动画播放器在抱棋模式直接拒绝 `runDistance()`。

已打开的网页仍运行打开时的 JS；更新服务器不会自动替换标签页中的旧模块，部署后需刷新。

## 新行为

- 空手接近和抱棋搬运均允许跑动。0.75m 以下继续走路/微调；较远距离优先选合法跑动档位，只补实际剩余距离，不固定加 0.6m 尾段。起跑和收步的原有减速曲线保留。
- 抱棋跑不是只加快角色平移：下半身复用已验证的 `run_start/run/run_stop`，上半身取 `chess_hold` 的固定双手托棋姿势；形成运行时的 `chess_carry_run_start/chess_carry_run/chess_carry_run_stop` 分层片段，跑步结束回到 `chess_hold`。
- 棋子仍采用托棋素材的基准位置，再根据实际手骨的角色局部变换同步起伏和转动；避免身体在跑、棋子却悬在固定高度。兼容 GLTFLoader 对 `hand.l` 等名称的净化。
- 不修改原始模型、骨骼权重或 GLB 动画，不把腿部跑动的摆臂轨道混入托棋上身。拾取、落子和服务端提交事件时刻保持原有契约。
- 普通近距离走路和明确的 `walk` 动作仍是走路；本次针对象棋两段自动站位及 `walk_to` 的长距离接近，没有把随机漫游或所有明确步行动作强行改成跑步。

## 验证

- `node --test tests/*.test.mjs`：**333/333 通过**；`npm run build` 通过。
- 分段器遍历 0.01–12m，验证距离不超目标、残差小于 2cm、档位合法；无效距离不会产生无限循环。
- 多种帧率和播放速度验证抱棋跑的位移、时长、下肢运动与托棋上身，不混入普通跑步摆臂。
- 加载真实角色的骨骼及动作、真实棋子持有曲线，验证整个跑动过程中左右手相对棋子的偏差均小于 2mm，实际位移精确为 1.744m。
- 隔离浏览器页面加载完整模型与棋子，播放到结束，显示 `chess_hold / 1.744m / 4.81s`；不连接 LLM、不改真实棋局。过程截图见 [抱棋跑预览](review-evidence/carry-run-2026-10-31/preview.png)。临时验收页面和服务已清理。

例：1.17m 接近由原来的纯步行约 11.2 秒，变成跑 1.104m 加微调 0.06m，约 4 秒，距目标还差 6mm。以上为动画时钟，不包含转身、拾取、思考或掉帧导致的额外墙钟时间。
