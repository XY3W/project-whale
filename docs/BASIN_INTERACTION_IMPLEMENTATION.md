## 4. 物品状态与唯一控制者

ObjectRegistry 保存 objectId、assetId、revision、state、world transform、linear/angular velocity、holderId/socket、可用交互和当前 throwId。状态至少包括：

- resting：地面或障碍上已经稳定；记录真实姿态和接触情况。
- reserved：被当前拾取任务锁定，还未抓到；保留原位置/姿态。
- held：手部挂接，动态物理关闭。
- worn：头部挂接，佩戴修正开启，动态物理关闭。
- flying / settling：物理模拟驱动，不能拾取。
- unknown：执行端失联/记录不完整；不能虚构落点或自动重投。

resting 可休眠，不需每帧无意义推进；held/worn 不参与动态受力。脱手后才切为 dynamic。每帧物品变换只能由 socket 或物理系统之一写入，不能挂在手上同时让物理更新。

角色继续使用原有动画与 Coordinator；不把角色改成自由刚体。增加简化躯干/头部运动学代理用于投掷物碰撞即可，不模拟角色受力或让盆把角色推倒。持有物品排除持有者碰撞；释放后只在确认脱离角色代理时恢复自碰撞，不能永久关闭，亦不能一开碰撞就把盆从手里炸飞。所有未验证的角色接触反馈保持禁用。

## 5. 局部物理实现

建议采用 Rapier JavaScript/WASM 接到现有 Three.js；不为此引入 React 或迁移渲染框架。实施时锁定所选兼容版本、确认构建可加载 WASM，不依赖“安装最新版一定可用”。本方案不要求自行编写刚体求解器。

官方依据：[刚体](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/)、[碰撞体](https://rapier.rs/docs/user_guides/javascript/colliders/)、[连续碰撞检测](https://rapier.rs/docs/user_guides/javascript/rigid_body_ccd/)。刚体负责积分/动力学，碰撞体负责几何接触；CCD 用于降低快速运动穿透风险。以下参数属于本项目建议，不是官方效果保证。

### 5.1 几何与参数

- 重力 (0,-9.81,0)，所有量使用米、秒、弧度/明确的角度转换。
- 地面有厚度；边缘为固定竖直边界，不使用 root.position clamp 冒充反弹。边界应覆盖合法投掷可达高度（初始可用 4m），与可见场地边缘对齐。
- 为当前指定障碍添加盒/凸形代理；未登记的装饰不自动参与碰撞。调试视图必须能显示哪些表面真实生效。
- 盆使用单刚体+多个凸碰撞体的组合；不能把中空盆整体取一个凸包封住开口。提供的 16 片墙+底部只是起点，检查薄壁、卷边、接缝及旋转落地时的稳定性。
- 初始质量 1.2kg、恢复系数 0.35、摩擦 0.6，均可配置。明确双方材质的合并规则，保证有效恢复系数小于 1。不要对每个子碰撞体都设置 1.2kg，导致总质量累加；不要按夸张视觉壳厚乘钢密度。
- 使用正常重力、接触摩擦和适量阻尼；反弹由求解器处理，不能又手动镜像速度一次造成双重反弹或增能。
- 不要求“速度每帧下降”（下落会加速）；检验的是接触前后能量耗散、弹跳高度逐次降低以及最终静止。

### 5.2 时间与停止

建议固定物理步长 1/120s，显示帧插值；启用 CCD，并在合法最高速度下实测薄障碍和角落。一次显示帧内可能发生多次碰撞，不能每帧只反射一次。性能不足可以调整步长，但必须重新测最大速度，不能任意削减速度掩盖穿透。

积压过多或标签页后台时采用明确的模拟暂停策略，不用一次巨大 delta 补算；暂停时不宣称落地，恢复前检查租约。无效数值、求解失败或严重穿透必须报具体错误。

建议停止门槛：有有效支撑接触、线速度 <0.03m/s、角速度 <0.15rad/s，持续 0.6 秒后允许休眠。仅空中速度低不能判停（抛物线顶点不是落地）。20 秒仍未稳定作为异常报告，不强制把盆吸到地面当成功。参数经实测后登记。

### 6.1 拾取范围和目标

从当前实际盆姿态计算可达盆沿握点，并检测是否被地面/障碍遮挡。优先提供多个沿口候选（可由圆周生成），不能只用一个埋在地面的固定握点。第一版只拾取 resting 物品，不接飞行或滚动物品。盆在地面时，必须先走到盆旁边并停稳，通过已验证的抓取范围/朝向/无遮挡检查后才允许 pickup；不能远程吸取、直接从地面戴头或直接从地面投掷。范围以模型与握点实测为准，不能仅用盆中心距离代替实际伸手可达性。

动画的地面/高度适配先限定验证范围，通过角色根位置微调的部分必须由明确移动动作完成，不允许 pickup 隐含走远或瞬移。动作内部可用有限手部 IK 对齐，但不能超出已验收关节范围。离得太远返回 OUT_OF_REACH，并提供可行站位；让 LLM 用现有合法距离和角度规划走近。

投掷后盆可能翻扣或侧躺；保持真实落地姿态，不强制扶正。至少验收正放、翻扣和稳定侧倾的拾取；找不到有效握点就返回 GRASP_UNAVAILABLE，不能把盆吸到手上。

### 6.2 抓取和脱手

抓取前先检查 object revision、预留任务和可达性；只有手实际到达时才切 held。对齐公式：`物品世界矩阵 = 手部socket世界矩阵 × 物品握点局部矩阵逆`。socket 是掌心/握持位置，不是未经校准的手腕原点。到达事件前完成对齐，不能在事件处跳动修正数十厘米。

脱手读取盆当帧世界矩阵，解除父子关系且保持世界姿态，再创建/激活动态刚体。初速度严格来自工具请求，不能额外叠加未告知的手部速度。首版角速度可固定为 0，由碰撞自然产生转动；不对 LLM 开放自旋参数。要求停稳投掷，避免角色移动速度与投掷速度含义混淆。

取消语义：grasp 前取消，撤销预留，盆留原处；grasp 后取消，盆保持手持；release 前取消，保留手持并安全收势；release 后取消，盆继续正常物理过程，不回手、不撤销飞行。

## 7. LLM 能力与场景信息

继续使用统一 CapabilityRegistry。只有资产、执行器和验收都通过的工具 enabled=true；未完成能力保留 disabledReason，不能仅因有模型文件就启用。

候选参数契约：

- `pickup(object_id)`：手空、对象 resting、revision 有效、距离和握点可达。
- `wear(object_id)`：目标盆由自己手持，角色停稳，头部装备槽空，戴帽动作及修正可用；成功后 heldObjectId=null、headObjectId=目标。
- `unwear(object_id)`：目标盆戴在自己头上，右手空闲，角色停稳；成功后 headObjectId=null、heldObjectId=目标。
- `throw(object_id, yaw_deg, elevation_deg, speed_mps)`：对象必须是手持盆，角色已停稳。yaw 为释放前角色当前朝向的相对角，正左负右；初始范围 [-45,45]。elevation 以水平为 0，正向上，初始 [-20,70]；speed 初始 [0.5,6]m/s。

wear/unwear 只在手与头之间转移同一个物品，不落地、不启用动态物理、不重新调用 pickup。戴头时要投掷，LLM 必须明确先 unwear 再 throw，宿主不得暗中补步骤。地面物品要戴头必须先走近、pickup，再 wear。四个物品动作均为串行动作，暂不允许放进 parallel；运行时校验通道与状态。

参数范围要和动画/碰撞验收同步，不允许 LLM 任意抬骨骼。如果用户想往背后扔，由 LLM 明确先 turn，再 throw；执行器不能暗中转身或改角度。方向公式复用项目现有坐标约定，yaw=0 指向 +Z、yaw 正向 +X。快照里的 forward 与真实变换一致。

throw 参数必须严格验证、拒绝越界，不静默 clamp。此版本允许提供离散的已验证仰角/动作档位，但需要明确登记 enum，并在执行前说明不支持的精确请求，不能宣称任意仰角均已实现。

快照增加对象 state、revision、position、rotation、linear/angular velocity、heldObjectId、headObjectId、graspCandidates、approachCandidates、pickupReachable（含原因）、affordances、throwId、是否接触地面和剩余执行预算。场地边界/碰撞障碍同步提供给 LLM，但具体每帧物理不是由 LLM 计算。

### 7.1 新动作提示词与计划边界

固定 system、planning、review 已在本地 llm-design 中补充物品自主决策规则。`BASIN_OUTPUT_SCHEMA.json` 是包含四个新动作的扩展模板；不是直接替换生产 enabled 清单。运行时仍由注册表生成当前可用 Schema，动作未完成必须禁用并说明原因。

LLM 自己选择合法 turn/walk 序列到达 approachCandidates。执行器只做验证和执行，不隐式自动导航。任一步移动失败，停止后续 pickup；根据当前快照重新规划，不沿用原预计坐标。沿途能力仍受原离散距离与边界约束；无法在预算内到达就诚实结束，不能绕过预算或把位置吸到盆旁。

同一计划可以包含“移动→拾取→戴头”等后续前置条件由前序步骤满足的串行动作：先整体验证结构/通道，再逐步依据真实最新状态验证前置条件；不能因为当前尚未 held 就提前否决整套合法串行计划。相反，前步失败时不得跳过它执行后步。

关注事件负责告诉 LLM 有盆，不负责命令 LLM 拾取。首次发现/进入关注范围按物品 revision 和事件 ID 去重；LLM 选择不处理后，不要每帧反复触发。完成一次交互或改变持有状态也不应强制开启无限“戴上→取下”循环。主动行为可以安静执行，不增加主动聊天或闲置模型轮询。

## 8. 执行结果、落地事件与重连

wear/unwear 各有真实转移事件，只有一个挂接所有者；转移前取消保持原 held/worn，转移后取消保持新的 worn/held，安全收势。佩戴形态按接触/离开时机过渡，不能摘盆后呆毛仍被压扁，也不能提前弹出穿盆。结果同时报告 heldObjectId/headObjectId、物品状态、挂接和修正权重，防止仅动画播完就报切换成功。

pickup 成功必须有实际挂接和 held 状态；throw 动画完成首先证明“已释放并完成收势”，不能证明命中或静止。结果携带 released、releasePose、requested/actual initial velocity、throwId 及当前 physicalState。

物品稳定后产生一次 `object_settled` 事件：真实最终姿态/位置、耗时、碰撞摘要、throwId。多次弹跳不逐次调用 LLM。与当前用户目标有关时，按现有事件机制触发检查；普通“扔出去”可先回复已扔出，不能凭预测宣布落点。目标要求“落到哪里/是否命中”时保留待检查关联，收到真实事件后再完成该部分。

任务取消/聊天关闭不取消已释放的物理过程。模型 API 报错也不撤销飞行，暂停角色自主行为即可。执行浏览器租约失效则停止其模拟与写入，把未对账物品标 unknown；不能让两个页面同时模拟。服务端保留释放与落地记录，必要时保留物理快照；重启/刷新证据不足时不假装落地、不自动重新投掷。先对账；无法可靠恢复时明确失败并提供开发重置，不把重置计为任务成功。

grasp/head_attach/head_detach/release/settled 都有 objectId、taskId、planId、stepId、eventId、throwId、revision/leaseEpoch；账本与去重逻辑复用当前修复方案。review 重试只检查实际结果，不能重复触发 release。

## 9. 建议实施顺序

1. **资产与坐标**：校验包、独立加载盆、环境光/反射、姿态与比例；制作戴帽修正的运行候选并验证，不修改原角色。
2. **物理沙盒**：独立测试页放地面、边界、一个障碍和盆；开发按钮输入速度/角度释放，验证反弹、CCD和静止。按钮仅开发使用，不新增用户地面点击移动。
3. **动作**：独立源副本制作 pickup/hold/throw/wear/unwear，输出事件表和多个视角预览，确认抓取/脱手连续性。
4. **状态集成**：ObjectRegistry、挂接/脱手、通道占用、持盆慢走、取消及对象 revision。
5. **LLM闭环**：注册工具、快照、真实结果、settled 事件、去重与错误重试；前置可靠性修复未通过时只留在沙盒，不生产启用。
6. **验收发布**：合并最新代码、测试、构建隔离产物，再发布。交付本地报告，不把设计文档或密钥丢到服务器。

## 10. 必须通过的验收

| 类别 | 验收 |
|---|---|
| 资产 | v2 尺寸正确、金属非黑块、GLB 节点保留；不用 v1 尺寸/握点/头部矩阵 |
| 戴帽 | 静止、点头、左右看、慢走不穿模；脱帽呆毛恢复；原母版与旧功能保持 |
| 拾取 | 正放/翻扣/稳定侧倾；先走近停稳才成功，远距离/被遮挡/飞行中拒绝，无隐含自动接近 |
| 决策 | 同一物品事件允许 LLM 选择忽略/走近拿着/戴上/投掷；脚本不固定选择，明确用户目标优先 |
| 切换 | held→wear→worn→unwear→held 可重复切换；物品不复制、不落地、不瞬移，不依赖重新拾取 |
| 状态前置 | 地面直接 wear/throw、戴头直接 throw 均拒绝；LLM 可规划正确中间动作 |
| 手持 | 待机、慢走、转向不落地穿模，不乱摆、不拉伸领结，手指与袖口合理 |
| 事件 | 30/60/120fps及跳帧情况下 grasp/release 各执行一次，事件前后不瞬移 |
| 投掷 | 前、左、右、上下仰角与速度边界，实际初速度/方向对应请求，不暗改参数 |
| 碰撞 | 地面、边缘、指定障碍、角落、快速薄壁碰撞，反弹路径正确，不穿越/增能 |
| 停止 | 多次反弹后在有效支撑上稳定；抛物线顶点不能被误判为停止 |
| 中断 | 抓取/释放事件前后取消，物品状态正确；已释放不会自动回手 |
| 恢复 | 检查重试不重投；双页面无双物理；刷新/断线/重启不虚构落点 |
| 反馈 | 收势成功与落地/命中分开，最终落点来自实际模拟而非预测 |
| 回归 | 原聊天、漫游、单页/多页控制权、旧动作/尾巴、位置保存仍符合当前规范 |

保存实际测试数据：请求参数、初始实际速度、事件发生帧、最终位置、碰撞次数、静止耗时、失败/unknown。单元测试用可控物理场景，真实浏览器验证动画与接触；少量真实 API 冒烟验证只在完整闭环就绪后进行。

交付 `docs/BASIN_INTERACTION_DELIVERY.md`（本地）：最终 Git 提交、资产 hash、配置与 schema、动画清单/事件、测试命令及结果、浏览器预览、API 是否实测、已部署范围和未完成项。不得把“有模型/有动画/有物理沙盒”写成“已实现全部互动”。
