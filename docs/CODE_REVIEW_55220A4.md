## 需要修复的发现

以下路径均相对本次服务器仓库；本地只读源码快照与可复现测试见末尾证据。优先级 P0 为凭据处置，P1 为行为正确性，P2 为协议/UI与维护补全。

### F01 · P0 · 非空密钥备份仍受 Git 跟踪

`.env.bak.1792948342` 备份仍被跟踪，`DEEPSEEK_API_KEY` 非空。本次只输出布尔存在性，没有复制、展示或验证密钥有效性。旧凭据需由持有人轮换，移除跟踪并补忽略规则；历史清理需结合远端/协作者协调，不能仅删当前文件就算关闭。未确认公开泄漏。

### F02 · P1 · 持物层让位方向写反，覆盖挖掘右臂

`src/character/LayeredMotionPlayer.ts:349–350`：`full_except_left_arm` 实际表示动作不包含左臂，应保留左臂 hold、让右臂交给动作；当前恰好跳过左 hold，仍应用右 hold。`src/main.ts:1049–1050` 又在任何互动时关闭左 hold、保持右 hold，进一步破坏双手组合。挖掘、右手投掷及另一只手持盆都会受影响。

实际 GLB 隔离复测：dig 0.7167s，启用当前持物接线后，右手相对原动画偏 **36.19°**、右上臂 **34.95°**。这是骨骼数值对比，不冒充浏览器观感测试。修复必须同时处理播放器 mask 与主循环门禁，按活动手而非“是否正在表演”决定 hold。

### F03 · P1 · dig_commit 未绑定当前任务，接触时缺少完整复检

`server/index.mjs:705–725` 只按连接身份、可选 epoch、请求自带 x/z 和可选 revision 结算；没有校验 taskId/generation/planId/stepId、右手饭勺、当前授权 dig 或格心距离。`src/main.ts:685–700` 也未在接触点复检，未提供实际勺头投影。

隔离 WS 在**没有任务、没有勺、没有 expectedRevision/epoch**时直接发 dig_commit，成功推进 rev=1。原本被取消/换代的迟到接触事件同样没有任务级防线。应先授权一个 dig 动作实例，再在提交时做租约+代际+版本+状态复检，拒绝脱离计划的提交。服务端在客户端模拟架构下仍不能独立证明骨骼接触，但必须校验授权记录、最新执行状态及工具参数的一致性。

### F04 · P1 · 手动结束后的 30 分钟暂停被任务收尾覆盖

`server/index.mjs:699` 设置暂停后，game_finished 触发模型收尾；`endTask():347–355` 无条件改写同一个 nextAt。进行中的旧任务收尾也会覆盖收摊暂停。

隔离假模型：保留 1,800,000ms 手动暂停，仅将普通等待缩为 1s，结束后 **9.35s** 已自行开出新局。使用独立持久化 `manualPauseUntil`，普通退避不得缩短它；手动开局才解除。

### F05 · P1 · 预算结束不取消执行，低帧率加长超时让问题更突出

`server/index.mjs:388–393` 180s 到期直接 endTask；没有 cancel_plan、取消确认或物品提交状态核对。隔离计时夹具压缩此定时器后，任务已 idle、cancel 消息 **0**。与此同时 walk/run 执行器可等数分钟，旧动作仍可能在走/投掷/挖掘。

`src/main.ts:541–626` 走近宏的连续 await 也没有统一取消信号；`ActionExecutor.withTimeout()` 只结束等待，不停止底层。应传递任务级 AbortSignal/epoch，超时进入 stopping/unknown，禁止直接回到可漫游 idle，提交点前后分别收尾。旧宏取消本轮为静态复核，不冒充新实机复现。

### F06 · P1 · 租约与重连仍可能接受过期状态、丢失任务证据

`server/index.mjs:202–204,739–741,790–798`：多数写操作仅比较 ws 身份；心跳超时 8.2s 后旧结果仍被接受。只有 reconciled=true 加坐标，就能把 unknown 任务清除，账本仍停在 dispatched。重启 `nextTask=100/generation=0` 还会复用并覆盖旧 `t100-p1-g1`。

`src/brain/BrainClient.ts` 在恢复坐标前调用 onReconcile；`src/main.ts:858–884` 只读仅改 UI，坐标和物品只应用一次。应以唯一 task/action ID、硬过期 epoch 和执行证据进行对账；新租约先恢复权威稳定状态/处理 unknown，再开放动作。以上服务端三个路径均重新隔离复现；未重做双浏览器实测。

### F07 · P1 · 新移动动作没有加入并行冲突与统一位移校验

`src/behavior/ActionExecutor.ts` 的 parallel 分支只将 turn/walk 算作移动通道，遗漏 run/walk_adjust；注册表也没校验通道占用。隔离测试中 parallel(run,turn) 同时调用两个底层函数。walk 仍只验证位移长度，朝向0却向 +X 走0.45m也报 succeeded；短步没有同等边界预检，从z=3.69走0.08仍报成功（真实主循环会夹到3.7，造成失败/滑步）。

由统一通道表拒绝共享身体的并行项；所有移动统一检查目标边界、方向、投影距离和横向误差。半圈有符号转向仍依赖归一化端点，需累计实际转角，不能直接用请求符号修饰结果。

### F08 · P1 · play(think) 仍为无限循环

`src/character/LayeredMotionPlayer.ts:78–79` 一次性列表没有 think；`src/main.ts:411–414` 却等待其自然结束。实际 GLB 推进40s后 upper 仍为 think；现在只是执行器改为60s超时，并未修复。将工具的 think 定义为有界单次动作，模型等待指示使用独立可取消的 UI/动画状态。

### F09 · P1 · 第四次执行结果仍不审核，事件可另起预算

`server/index.mjs:830–835` 在最后一次 review 前结束任务。假模型测试：4份执行结果只有4次调用，缺少最终第5次审核。`endTask` 又调度剩余棋盘事件，`scheduleEventTurn/startEventTask` 不经过 tickAutoPlay 的小时计数与 nextAt，所以未消费的第4轮 board_updated 可开启新任务、新预算。后者为代码路径确认。

保留4次 execute 上限，允许一次只收尾的最终 review；事件统一走同一个调度准入与小时计费，不可依靠新 task 重置预算。

### F10 · P2 · dig 重发不幂等，早期错误丢失关联 ID

`server/index.mjs:706–720` 未保存 actionInstanceId 结果。相同实例重发第一次成功、第二次变 ALREADY_REVEALED/STALE_REVISION，丢失“已经提交”的事实。早期 NOT_ON_BOARD/STALE_LEASE 返回不带实例ID，客户端 waiter只能6s后误报TIMEOUT。实例结果应落盘、重放相同结算，所有成功/失败回包带原ID。

### F11 · P2 · 收起棋盘不会同步到其他页面

`src/brain/BrainClient.ts` 的 session_state 分支使用 `if (msg.game)`；服务端广播 game:null 时只读页面忽略。按钮发起页另收到 game_state 因而能清除，其他页面保留旧盘。直接执行该类的消息分发，playing后发null，只收到一次onGame，证实未清除。应判断字段是否存在，而不是值是否为真。

### F12 · P1 · 飞行状态被旧手持状态替代

`server/public-state.mjs:36–39` 既用于持久化也用于实时状态，把flying/transferring回退为previous稳定状态。复测worn rev10→flying rev11，模型/重连快照仍显示worn rev10。应分开实时状态、恢复检查点和unknown；可保留恢复检查点，但不能谎报物品仍在手或头上。

### F13 · P2 · 完成账本覆盖执行证据，用户回合不能保持空回复

`server/index.mjs:586–593` finish时done条目只剩reply，执行报告消失；用户回合空speech仍被替换为“好了。”。两项均复现。自主回合空回复已改好，需保留这个进步。新音效/活跃模式会更依赖事件证据，应该合并账本字段而非覆盖，并明确公开话语只发送一次。
