## 1. 目标与职责

完成四项备忘录需求：

1. 左手盆增加盆口朝外的反向持法，能与当前盆口朝内持法切换。
2. 反向持盆且右手持勺时，可以敲一下或连续敲几下。
3. 钢盆与勺敲击、盆碰地/碰边界/碰其他已启用碰撞物时发声，按实际碰撞强弱调整音量；同类提供多个音色变体随机选择。
4. 安静/活跃模式可切换；活跃时LLM主动安排调皮、有趣的行为，最长10分钟，到点允许完成当前事情；进行中的游戏优先，禁止插入活跃模式闲逛表演。

**Codex负责动作、资产与音频制作、素材参数和交付文档；DeepSeek负责服务器/前端代码、物理接线、调度、提示词接入和运行时验收。** 不再把新增动作制作交给DeepSeek。现有角色、盆、直杆木柄勺保留；所有编辑新建副本。

先修F01–F09/F12等底层问题，再开放新能力。资产未交付或运行时未通过时，能力注册为disabled并给出原因，不给LLM一个实际不存在的动作。

## 2. 本轮采用的模式解释

为兼容最新已上线的自主扫雷，采用以下解释：

- **安静**：不触发一般性的主动找事/主动聊天；保留机械漫游、用户指令，以及已有的扫雷事件与自主续玩机制。扫雷是已有专用行为，不因切换安静而被中止。
- **活跃**：在没有用户任务、聊天、游戏和恢复事务时，额外允许LLM主动选择已有的有趣行为；可以简短自言自语，但不要求每次都说话。
- **游戏优先**针对自主行为：进行中的扫雷压过一般调皮行为，但不压过用户停止、聊天接管、断线恢复和安全收尾。不会为了游戏拒绝用户控制。
- 上述安静模式仍保留自主扫雷是本方案的兼容性解释；若用户希望安静也不自主开新局，只改调度策略开关，不能偷偷删掉已有功能。

模式切换由用户UI控制，LLM不能自己开启活跃、续期、改预算或解除用户暂停。初始安静；用户点击“活跃10分钟”时服务端生成modeEpoch与到期时间，右上/设置区显示模式和倒计时（不要占用角色聊天入口）。活跃中重复点击不延长倒计时，提供“切回安静”。

## 3. 先补执行和恢复闭环

### 3.1 统一动作生命周期

使用任务/计划/步骤/动作四级唯一ID，ID跨服务重启不重复。执行消息固定带原始leaseEpoch和generation；迟到结果不能改用新epoch。所有带副作用消息必填这些字段，缺失拒绝。

生命周期：accepted → running → committed（可能多次有编号的敲击事件）→ settling → completed；错误可进入cancelled/failed/unknown。预算结束只阻止新动作并请求停止，收到稳定/不可确定证据前不能宣布idle并漫游。

- 取消信号传递到turn/walk/run/adjust、走近宏、动画事件、道具曲线、等待器和网络请求；每个await后和事件提交前检查。
- 单步超时停止实际动作，不仅结束Promise等待。旧闭包不得继续走下一段。
- 接触/脱手前取消：保持原持有/棋盘状态；脱手后取消：保留刚体继续落地，禁止回手；dig已经结算则保留揭示，不回滚成未挖。
- 持有状态同时包含实时state和最后稳定checkpoint。重连先对账，未知动作不重放；checkpoint不得冒充当前已知状态。
- 最后第4次执行允许只收尾的review，禁止第5次execute；超限事件可等待后续预算窗口，不能另起任务绕过。
- think工具为有界单次；模型等待提示为独立UI/可取消表现。完整消息预算、固定原目标与累计摘要用于每次planning/review。

### 3.2 动作通道与持物层

用注册表统一描述资源：body_locomotion、left_arm、right_arm、head_attachment、tail、item:<id>。执行器和模型校验器使用同一冲突规则；run/walk_adjust不得与turn/walk等同时占身体通道。

按实际轨道mask接入：

| 动作类型 | 左臂 | 右臂 |
| --- | --- | --- |
| idle/walk/run/adjust | 持盆则应用对应hold | 持勺则应用hold_scoop |
| dig/pickup_scoop/throw_scoop | 持盆hold继续 | 交给主动片段 |
| pickup/throw/wear/unwear_basin | 交给主动片段 | 持勺hold继续 |
| 盆内外持法切换 | 切换片段 | 持勺hold继续 |
| knock_basin | 交给专用双臂片段 | 交给专用双臂片段 |

`full_except_left_arm`意为保留左臂hold；反侧同理。不能在主循环另加一套与mask矛盾的“有表演就禁左臂”。传统greet等若与持物冲突，禁用并说明原因或制作适配片段，不能硬叠。

### 3.3 扫雷与自动调度修复

- 持久化独立 `manualPauseUntil`；`nextEligibleAt=max(manualPauseUntil, cooldownUntil, backoffUntil, budgetAvailableAt)`。用户手动开局显式解除手动暂停；任务结束不能缩短它。
- 所有事件发起、自主续玩和活跃机会统一经过准入控制，计入同一API预算。事件合并不代表可以跳过暂停/上限。
- dig开始由服务端登记授权实例：task/plan/step、gameId、revision、格子、饭勺ID、租约与代际。动画接触再次核对右手、站稳、格心距离、勺头投影同格及棋盘版本。服务端不接受任意客户端坐标绕过授权。
- `dig_commit`按动作ID持久幂等，重复回放原结果，所有错误带请求ID。接触后丢回包可查询原实例结算，不能猜失败再挖。
- 手动结束/换局使旧dig授权失效；结束事件可以只收尾审核，不得顺带开启新局。收起game:null同步所有页面。
- 记忆确认/删除、source_quote与原消息绑定、历史保留、诊断预览退出恢复等旧验收项保留，不因为新增玩法而丢弃。

## 4. 反向持盆的动作与状态

复用唯一物品 `basin`，不生成第二个盆。`state=held,holder=left_hand`时增加 `grip=inward|outward`；盆口向量相对身体定义朝内/朝外，不依靠屏幕角度判断。旧持盆记录迁移为inward，地上/飞行中/头上没有有效hand grip。

新LLM工具（拟定接口，范围在资产验收后冻结）：

```json
{"action":"set_basin_grip","object_id":"basin","grip":"outward"}
```

前置：盆在左手、身体站稳、当前没有转移/投掷/戴取动作；目标与当前一致时幂等成功不重播。动作必须让左手和盆同步旋转，避免改挂点瞬移。提交后再更新逻辑grip；过渡取消按已提交与否回到对应稳定端。

Codex交付新内→外、外→内切换片段和外持hold；两端绑定矩阵、切换commit时刻与hold接缝一起验证。矩阵和时刻写入catalog，不在应用代码或此方案里猜。

首版沿用既有戴盆/投掷片段需要inward；如果outward时想戴/投，LLM显式先set_basin_grip(inward)，宿主不得悄悄切换。取下盆后的grip=inward。以后有外持投掷资产再开放能力。

## 5. 敲盆：动作、参数和提交

```json
{"action":"knock_basin","object_id":"basin","tool_id":"rice_scoop","count":3,"tempo":"normal"}
```

一期count整数1..32；tempo仅normal，具体节奏由Codex成片确定，不开放任意加速、力度或敲击位置。count=1即单次，多次为有限连敲，不开放无限loop。动作原地完成，独占双臂及相关道具，不能与run/dig/throw并行。

前置：左手盆outward、右手同一饭勺held、站稳、无未结清转移；游戏正在进行时不允许活跃调度插队，用户明确要求敲盆则由用户任务抢占游戏规划，先稳定停下再执行。

Codex交付敲击准备、单次击打循环、收尾，或等价完整可循环段；双臂与勺头接触点需与最新直杆勺匹配。敲击头不能穿盆，不能拉长手臂，盆/勺在原挂点约束下完成。idle/run双持和握法切换也需验证。

每次真实接触产生 `knock_contact`，唯一键 `(actionInstanceId, hitIndex)`；由运行时确认工具/盆状态与当前动作，再记入结果并发声。LLM只决定count，不直接发声音事件。掉帧跨事件也只结算一次；取消后不再发生新的敲击。已敲次数保留，result明确requestedCount/committedCount/stopReason，不能把2/4次报告成全部完成。

重复网络消息不会重复声音；刷新/重新订阅不补播历史音效。主动敲击以动画接触事件发声，不再额外按同一接触的物理回调发第二声。

## 6. 盆的声音与局部物理

### 6.1 资产交付

Codex制作原创/有明确可用授权的金属敲击、落地、侧面反弹三类素材；建议每类3个变体，保留WAV源并交付浏览器格式。包含轻击/重击的音量归一化基准、有效起点、自然衰减、时长与响度说明；来源/授权、hash和试听页一并交付。不能把同一音频随意增益到削波，也不需要本轮引入语音合成。

### 6.2 音量与随机性

碰撞强弱使用接触法线方向的相对入射速度 `vn=max(0,-dot(vRel,n))` 或经标定冲量；不能用碰撞后的速度、也不能仅用切向擦过速度。建议初始标定 `gain=clamp(k*vn,0,gainMax)`，阈值和k由实际试听确定。此为可调方案参数，不是已验证音量。

每次符合阈值的碰撞按类别随机取样，避免连续重复同一变体；可轻微pitch变化，但先用素材差异，不让金属声变成玩具哨声。接触持续/休眠抖动不重复响；同一碰撞对设置短去抖窗口，保留后续真正反弹的声响。短时间多接触需限制并发声源，防止爆音。

### 6.3 物理接线边界

当前每个PropItem各自创建BasinPhysics/Rapier.World，世界内只有自己的物品与地面/墙；**盆和勺之间不会发生跨世界物理碰撞**。新增“碰到其他物品发声”时先迁移为共享的局部物品物理世界，统一步进、碰撞事件与物品ID，而不是在彼此独立的世界上猜碰撞。

- 范围仅盆、勺及明确启用的场地静态碰撞体；角色继续动画驱动，不引入布料/毛发/整个人体刚体。
- 手持/佩戴由骨骼驱动，不受重力；脱手时原子切换dynamic；落地稳定后休眠。手持物如需参与碰撞，应为可识别的kinematic/sensor策略，避免反作用力拉扯角色。
- 盆和细长勺各自配置质量/形状/惯量/摩擦/反弹，别把整个勺子当盆圆柱；保留CCD与有限休眠规则。
- 每个碰撞事件携带物品对、接触点、速度/冲量、事件ID；声音不影响物理结果，也不直接触发每一下的LLM调用。

浏览器AudioContext需要用户首次点击解锁。未解锁时静音并提供“开启声音”，不要缓存随后一次性播放旧撞击。提供总音量/静音；后台与只读页面默认不重复播放同一场景的声音，需明确一个声音呈现端。LLM失败或切安静不等于全场静音，音量设置独立。

## 7. 活跃模式调度与10分钟到期

由服务端保存 `mode,modeEpoch,activatedAt,expiresAt,drainTaskId,drainDeadline`，页面刷新不重置时长；重启检查绝对时间，到期恢复安静，不重新赠送10分钟。备忘录明确最长10分钟，因此游戏/聊天占用期间倒计时继续走，不暂停累计。

优先级：用户停止/租约失效/恢复收尾 → 用户聊天与明确指令 → 正在进行的游戏 → 活跃机会 → 机械漫游。进入聊天仍停止漫游并朝向用户；2分钟无键盘输入的原退出规则保留。

活跃机会建议初始每30–60秒检查一次，仅在空闲、聊天关闭、无playing游戏、未到期且有执行端时创建。真正调用前先停止机械漫游并等待稳定，再展示“思考中”。每次只生成一个短目标，使用现有有限参数能力，不提供任意脚本或骨骼写入。

预算建议沿用自主任务每小时最多300次模型调用（沿用服务器现有默认值，可由AUTO_MAX_CALLS配置；**游戏和活跃共用小时上限**），活跃单轮最多4次执行、180s；包括最终只收尾review的实际模型调用均计费，并另记请求/token估算。用户消息不计入自主次数但有各自任务预算。连续2次无进展，停止本次活跃机会并退避，不反复叫LLM原地试错。所有事件任务同样走此入口。

到期语义：

1. 到10分钟立刻关闭新的活跃机会；UI显示“安静 · 正在收尾”而不是继续延长倒计时。
2. 若当前有活跃任务，冻结其taskId和原目标。允许这一个已有有限计划完成、进行一次只收尾review；不再接受追加execute_plan把“当前事情”无限延长。
3. 保留原任务180s总预算，不重新计时。超预算/失租约按正常安全取消与unknown对账处理。已脱手物品继续有限物理落地。
4. 若正在游戏/用户任务，它们按各自规则继续；到期只关闭活跃调度，不能打断游戏。
5. 用户主动切回安静立即禁止新活跃计划，当前动作到安全边界结束；明确“停止”使用更高优先级取消。模式切换不瞬移物品。

点击结束扫雷后的既有手动暂停（当前默认持续到用户再次手动开局）继续约束自主开局；活跃模式不得通过“找事做”重新开局绕过它。游戏未完成时活跃也不能把勺子投走导致游戏自我破坏。
