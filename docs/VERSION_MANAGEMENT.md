## 标准流程

1. **开始前核对。** 确认当前目录、分支、`git status`、最近提交和远程状态。检查对方是否有进行中的修改；不覆盖、不重置、不清理不属于本次工作的改动。先从 GitHub 安全同步 Mac 的 `master`；有冲突、分叉或未提交改动时，先检查并妥善整合，不要强制覆盖。
2. **在 Mac 开发。** 共享同一工作目录；两位开发者同时处理相邻文件时先协调，避免覆盖彼此的改动。保留原始模型和原始素材，模型修改遵循项目已有副本约定。
3. **在 Mac 验证。** 按改动类型运行必要的构建、测试和实际效果检查；涉及动作、模型、交互或界面时，尽可能进行针对性视觉或运行时验收。记录未覆盖的范围；测试通过不能保证不存在所有 bug。
4. **审核并提交。** 检查 `git diff` 和暂存区，按明确路径暂存本次需要的文件，不使用会把大量未知文件一起加入的 `git add .`。确认没有密钥、运行数据、日志、个人信息或未经授权的素材，然后提交清晰的说明。
5. **推送 GitHub。** 将经过验证的提交推送到 `origin/master`。推送被拒绝时先获取远程更新并检查分歧；不可强推、重置或改写他人历史，除非用户明确要求并理解影响。
6. **服务器拉取并部署。** 检查服务器当前状态、待部署提交、运行服务和必要的部署备份；从 GitHub 获取提交，用快进方式更新 `master`，不在服务器修改源代码。服务器若有未提交改动或分叉，先保留并调查，不用 reset、clean 或覆盖式同步处理。
7. **部署后核对。** 验证服务器当前提交等于已推送提交，按实际服务配置构建并发布，检查服务状态、网页与受影响的关键功能。需要重启时先考虑正在执行的任务和用户影响；如部署或验证失败，应如实报告并依据备份恢复，不能称为部署成功。
8. **交接。** 向用户说明做了什么、提交号、推送和部署状态、测试结果，以及尚未完成的人工验收或已知限制。

## 部署细则

- 服务器上的 `.env`、`data/`、真实用户记忆、定时任务和其他运行数据属于独立的运行环境，不应因代码同步、构建、部署或回滚被覆盖、提交或删除。
- 先检查实际部署方式和当前服务状态，不照搬过时的环境文档。当前已知服务为 systemd 的 `whale.service`，工作目录是服务器主工作区；部署前仍需核实其配置和运行状态。
- 构建产物应来自**实际部署的提交**；替换前按需备份当前产物。静态资源更新应考虑已打开页面仍可能请求旧的带哈希资源，避免无必要地删除它们。
- 不要将未推送的本地源代码或临时实验目录直接复制到服务器作为正式发布；有紧急修复时先与用户确认是否需要临时偏离流程，之后再同步回标准流程。
- 回滚也需要核对代码版本、构建产物和运行数据兼容性；不要对用户数据进行盲目回滚。

## Mac 的 GitHub SSH 授权

- 此 Mac 当前使用的项目远程是 `git@github.com:XY3W/project-whale.git`。可使用已有的 `~/.ssh/id_ed25519.pub` 公钥；不要上传、粘贴或复制同名但不带 `.pub` 后缀的私钥。
- 在 Mac 终端执行 `pbcopy < ~/.ssh/id_ed25519.pub`，将公钥复制到剪贴板。在 GitHub 的 **Settings → SSH and GPG keys → New SSH key** 中，选择 **Authentication Key**，粘贴公钥并保存。登录、双重验证及最终授权由用户完成；如果账户没有目标仓库的写权限，还需要仓库所有者授予写权限。
- 公钥指纹可用 `ssh-keygen -lf ~/.ssh/id_ed25519.pub` 查看；它用于确认添加的是哪把钥匙，不是 GitHub 服务器的主机指纹。
- 首次连接若提示确认 GitHub 主机身份，应与 GitHub 官方公布的主机指纹核对，不要关闭 SSH 主机密钥验证。参考：https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints
- 执行 `ssh -T git@github.com` 检查认证：显示 GitHub 用户名并提示认证成功即可；GitHub 不提供 shell，因此该命令常以状态码 1 退出。认证成功仅说明身份可用，不代表对项目一定有写权限；仓库写权限以账户授权和实际推送结果为准。
- 正常开发应在 Mac 项目目录直接执行 `git fetch`、提交和 `git push origin master`。不能连接时先诊断主机密钥、SSH 身份和仓库权限；不要复制服务器私钥到 Mac、关闭安全校验，或把凭证提交到仓库。授权未完成时保留本地提交并明确报告，不宣称已推送或部署。
- GitHub 官方授权说明：https://docs.github.com/en/authentication/connecting-to-github-with-ssh/adding-a-new-ssh-key-to-your-github-account

## 密钥与隐私

- API key、token、私钥、密码、`.env` 及其备份永不提交或粘贴到文档、日志、终端输出、提交说明或截图。服务器 `.env` 应保持私有权限并被 Git 忽略。
- 提交前检查暂存的文件及内容；`.gitignore` 不能移除已经进入历史的密钥。如果发现密钥进入 Git，立即通知用户并安排撤销、轮换；清理历史不能代替撤销密钥。
- 不主动向外部服务发送聊天、记忆、日志或其他用户数据。演示与测试优先使用隔离数据和模拟接口；真实模型请求产生的费用和对运行角色的影响要纳入考虑。
