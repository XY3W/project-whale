## 跑动与精细移动

| 片段 | 时长 | 世界前进距离 | 用途 |
|---|---:|---:|---|
| run_start | 0.40s | 0.080m | 起步 |
| run | 0.80s/循环 | 0.320m/循环 | 基础跑速 0.40m/s，单步 0.16m |
| run_stop | 0.40s | 0.064m | 收步 |
| walk_adjust_02 | 0.80s | 0.020m | 短步微调 |
| walk_adjust_04 | 0.80s | 0.040m | 短步微调 |
| walk_adjust_06 | 0.80s | 0.060m | 短步微调 |
| walk_adjust_08 | 0.80s | 0.080m | 短步微调 |

跑速约为原走速 0.1125m/s 的 3.56 倍；步长比原 0.09m 大。上述片段全部以 lower / upperBase 两层发布，不带角色根节点的世界位移。骨架内部的小幅骨盆运动不能被当作根位移重复应用。

世界位移与片段严格配套：run_start 用 `0.08*u²`，u=t/0.4；run 用 `0.4*t`；run_stop 用 `0.064*(2u-u²)`，u=t/0.4；短步用 `distance_m * (3u²-2u³)`，u=t/0.8。u 均截在 [0,1]。一个完整跑动指令距离为 `0.144+0.32N`，默认能力草案取 N=1..11；在完整周期 phase=0 进入收步，不能任意相位切片。

正常目标距离用显式 run、walk、walk_adjust 组合；微调按 2cm 一档，最多约 1cm 的量化残差仍需由最终站位与接触检查判定。禁止悄悄传送补齐残差、超跑再倒退，或任意放大骨骼动画。近距离不用 run_start+run_stop 冒充微调。

首版注册表固定 1×。作者建议的跑动变速候选 0.85–1.15 只用于后续运行验证；必须同时缩放时间与世界位移，并通过起停/边界检查后才开放。急停、失去租约、预算耗尽立即禁止继续位移，不能以“等收步”为由继续执行后续指令。

## 饭勺与挖掘

| 动作 | 时长 | 事件 | 结束状态 |
|---|---:|---|---|
| hold_scoop | 2.00s 循环 | 无 | 右手持勺 |
| dig | 1.70s | 0.72s：dig_contact | 右手仍持勺 |
| pickup_scoop | 2.00s | 0.48s：toe_lift；1.18s：hand_catch | 地面→受控抛接→右手持勺 |
| throw_scoop | 2.00s | 0.68s：release | 交给物理，后续以真实物品状态为准 |

用户已确认用脚尖轻挑、右手接住，保留短手臂原身材。初始饭勺在地上，toe_lift 前保持原世界位置；只有实际到达参考站位且前置条件仍满足才触发。toe_lift 后是 `transferring`，沿连续曲线到手，区别于真正投掷的 `flying`。正反面平躺共用 pickup_scoop 身体片段，分别使用 pickup_scoop / pickup_scoop_face_down 道具曲线；运行时按真实物品法线选 variant，不改变地面物品姿态来迁就动画。途中正常取消延迟到安全接住点；页面关闭/租约丢失按事件账本恢复，不能丢物或多复制一把。

首版已制作的拾勺姿态为：静止、平地、勺面朝上或朝下、按 catalog.pickupVariants 对齐。抛落后侧立或斜放的拾取尚未覆盖，不应自动扶正；向 LLM 返回 OBJECT_POSE_UNSUPPORTED，并保留原物体。这是下一批补充姿态的边界，不可在代码中隐藏。

挖掘表现为站稳、右手把饭勺向前轻探再收回，保持左手盆的净空。按用户要求表现挥勺，不要求短手臂真的把勺头按到地面。`effectPoints.dig.localPoint` 是勺面的局部点，求其世界位置再垂直投影到当前格面；角色根所在格、有效站位和勺面投影必须同时落在目标格，才能在 dig_contact 结算。不要拿头的位置或盆的位置作为挖掘目标。

物品单位米，glTF +Y 上、+Z 角色前方。饭勺约 30.4cm 总长；模型握点原点与几何中心不同。无外部纹理、无骨骼、无脚本依赖；分开的闭合勺面/握柄结构共 1,566 个建模顶点。碰撞建议使用交付的两段凸代理，质量/反弹/阻尼属于待物理沙盒验收的参数，不以视觉网格充当高精度动态凹碰撞体。

## 左手盆与双手分层

盆五段动作 ID 保持 pickup_basin / hold_basin / throw_basin / wear_basin / unwear_basin，均已重新生成左侧动作与左手挂接矩阵。原有事件时刻保持：拾取 1.05s，投掷 0.88s，戴盆 0.70s 脱手/1.95s 到头，取盆 0.65s 离头/2.00s 到左手。

- `bindings.leftHand` 对应盆的 hand.l；`bindings.rightHand` 对应饭勺的 hand.r；head 只给盆用。
- 实际物品世界变换 = 骨骼 matrixWorld × binding.matrixColumnMajor。矩阵乘在完整 glTF scene 的单位 wrapper 上，不再加自猜的轴旋转或缩放。
- hold_basin 覆盖 8 根左臂轨道；hold_scoop 覆盖 8 根右臂轨道，均为绝对姿势，不是 additive。
- 主动盆动作排除右臂轨道，主动饭勺动作排除左臂轨道；另一只已持物的手持续由对应 hold 层驱动。空手臂由 base 提供。不能用全局混合权重把另一只手同时压低。
- 运动层控制下身，手持层覆盖对应手臂；摆尾仍为独立层。greet 等占用手臂的旧手势必须由能力兼容表处理，不能盖过正在持物的那只手。
- 戴/取盆继续使用轻巧卡通抛接和 Basin_v2_Wear_Crown_Tuck；饭勺没有 wear 入口。右手有饭勺不影响把左手盆戴到头上。

事件必须按跨越时间区间触发一次，而非浮点相等。掉帧跨过两个事件要依次在准确事件时间求骨架、更新 matrixWorld，再提交账本。事件 key 带 task/generation/actionInstance/objectId。飞行物落地可能早于动画结束，动画结束不得写回 flying。

## 检查范围与接入门槛

已做 Blender 原生 rig→公共骨架的蒙皮对比、GLB 导出回读、运行时挂接矩阵对比、循环首尾、地面/持物接触采样、双手组合正侧背预览及原资产 hash 检查。具体数值见 reports；这些是离线资产检查，不代替服务器接入结果。

基础跑动起步→循环→收步的骨矩阵接缝检查通过，四档短步的支撑脚采样漂移最大约 0.096mm。基础跑动循环首尾一致；支撑脚离线采样仍有约 3.4mm 的位移误差，不能声称完全零滑步。角色与物品接触是离散表面采样，保留握持/脚尖挑起的局部接触容许区；不是连续碰撞证明。原盆落地约 0.061mm 数值偏差，物理放置时应按碰撞体底部校准，不挪动角色补偿。
