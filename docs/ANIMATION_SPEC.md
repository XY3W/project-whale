# 动作生产规格与待解决方案

> 给模型侧（GPT）的交接文档。目标：在 V8 绑定上产出「可被 LLM 选择、可分层叠加」的动作库。
> 相关设计：[DESIGN.md](./DESIGN.md) v0.7 第 3 节「分层」。
> 日期：2026-10-24

---

## 1. 背景

用户已确认采用新方向，替代此前实时参数驱动骨骼方案：

**预生成动画片段 → LLM 根据情境选择片段 → 运行时播放与分层混合。**

现在的问题是：V8 绑定上**没有任何身体动作**（只有一条摆尾）。

旧 V4 导出片段不能未经验证直接挂到 V8 上。需区分源 Blender 动作与导出的运行时骨架：V8 修复记录确认原有骨骼静止矩阵未变，因此不能仅凭旧导出重定向失败认定源动作不可复用。先在 V8 副本上验证旧源动作、重新烘焙；失败时在 V8 上重做。所有正式片段必须匹配同一运行时骨架版本和参考姿态。

---

## 2. 用户刚提出的调整：分层动画

要求手、脚、尾巴、脸可以各自独立播放，例如：

- 走路的同时挥手
- 说话/待机时眨眼，与身体动作无关
- 摆尾不受上身动作影响

分层表：

| 层 | 覆盖骨骼 | 片段 |
|---|---|---|
| base | 全身（含手臂摆动） | idle_stand / walk（run / sit_* 后续） |
| upper | 肩、手臂、手、头、颈 | greet / notice / nod / look_* / think |
| tail | `WhaleTail_01..06` | tail_idle / tail_swish |
| face | 形态键（morph） | blink / 表情 |
| gaze | 暂禁直接修改头骨 | 先用预制 look；程序化跟随需另行验证 |

**实现原理**：轨道切分限制影响范围，但重叠轨道会按权重混合，不会自动覆盖。base 导出后拆成同步的 lower 与 upperBase；手势 upper 与 upperBase 使用互补权重，lower 不受影响。第一版 upper 提供完整上身姿态，结束后恢复当前基础上身，而不是全身回 idle。

## 3. 绑定与命名基线

- 文件：`tail_v8/Character_WhaleTail_Attached_v8.blend`
- 骨架：`rig`，376 骨，95 根 deform
- 身体网格：`SK_Character_Master`；尾巴网格：`WhaleTail`
- 单位：米，30 fps，角色朝 +Z（glTF 空间）
- 尾巴骨：`WhaleTail_01` … `WhaleTail_06`（父级 `WhaleTail_Root`）
- 头颈：`head.x`、`neck.x`、`c_head.x`、`c_neck.x`、`subneck_twist_1.x`
- 手臂（变形骨）：`shoulder.l/r`、`arm.l/r`、`forearm.l/r`、`hand.l/r`，
  另有 `arm_twist.*`、`forearm_twist.*`、`*_stretch.*` 等辅助骨由约束驱动
- 躯干：`spine_01.x` … `spine_05.x` 及对应 `c_spine_*`

## 4. 待解决方案（需要模型侧答复或共同确认）

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| S1 | **移动片段用根运动还是原地？** | 决定移动控制器与滑步处理 | 推荐原地 + 运行时速度匹配；若用根运动，请说明提取方式 |
| S2 | **upper 层与 base 层在手臂上冲突** | 一边走一边挥手时，base 的摆臂会和挥手打架 | 推荐 upper 片段只含上半身骨，且运行时让 upper 完全覆盖手臂；base 继续驱动腿 |
| S3 | **片段的首尾姿态** | 淡入淡出是否自然 | 每段首尾尽量接近 `idle_stand` 的同一姿态，并在交付说明里注明 |
| S4 | **导出时是否会烘焙全部骨骼** | 若导出器给每段都写全身轨道，分层失效 | 导出必须**只包含该层骨骼的动画轨道**，或提供可裁剪的中间文件 |
| S5 | **脸部形态键损坏** | blink / 表情无法启用 | 需要单独修复；修复前 face 层保持禁用 |
| S6 | **领结权重缺陷** | 摇头、抬手时领结剪切 | 建议与动作同批修复，相关动作发布前修复并通过组合验收；未通过则禁用相关动作 |
| S7 | **动作的进入条件与冷却** | 运行时状态机需要元数据 | 每段交付 `loop`、`duration`、`interruptible`、`cooldown`、`allowedStates` |
| S8 | **LLM 是否可调速度/幅度** | 影响接口设计 | 播放倍率候选 [0.75, 1.25]，须实测后公布；执行器按移动速度派生倍率，LLM 不同时独立控制两者 |
| S9 | **尾巴是否独立片段** | 决定 walk/idle 里是否含尾巴 | 推荐独立成 tail 层片段，idle/walk 不写尾骨 |
| S10 | **打断与过渡时长** | 影响观感 | 以 0.2–0.3s 淡出为起点；upper 结束恢复当前 base 上身，不停止走路 |

## 5. 动作清单与规格

### P0（先做这五段，能跑通完整演示）

| id | 层 | 循环 | 时长 | 轨道范围 | 说明 |
|---|---|---|---|---|---|
| `idle_stand` | base | 是 | 4.0s | 全身（不含尾骨） | 呼吸、重心微动、头部轻微晃动 |
| `walk` | base | 是 | ~1.2s/循环 | 全身（不含尾骨） | 原地走，步频稳定 |
| `tail_idle` | tail | 是 | 3.0s | 六段活动尾骨 | 小幅摆尾，先验证与移动叠加 |
| `greet` | upper | 否 | 2.5–3.0s | 肩、臂、手、头 | 抬手挥手，结束时回到接近 idle 的姿态 |
| `notice` | upper | 否 | 1.5s | 头、颈、肩 | 被点击的转头反应 |

## 6. 轨道切分约定（最关键）

制作与导出是两个步骤：Blender 可对所属动作的控制器打关键帧；导出前先求值并烘焙约束驱动的完整变形结果，再按运行时依赖切分轨道。不得先删除辅助骨再求值。

- 固定同一骨架版本、层级、参考姿态和局部 TRS 约定；交付骨架签名与节点映射。不同片段不得各自裁剪出不兼容的层级。
- 运行时轨道须覆盖实际影响蒙皮的扭转、拉伸、颈部和缩放修正骨，包括必要的位置与缩放轨道；不能只导出手臂主骨旋转或 c_* 控制器。
- base 分为 lower 与 upperBase 两组，时间和相位保持同步；upper 使用与 upperBase 一致的完整上身节点/属性集合。共享躯干轨道只能归一个组；跨组依赖须在组合姿态中验证。
- 尾巴层只动画 WhaleTail_01..06。WhaleTail_Root 保留骨盆锚定参考变换，不作为摆尾参数；若基础动作确实需要它的补偿轨道，归 base 管理并验证。
- face 只包含形态键，修复前禁用。gaze 不直接覆写头骨。
- 保留完整烘焙中间产物；正式分层片段提交 node + property 轨道清单、归属及辅助骨依赖说明。不能以“出现 376 个节点”判定烘焙失败；验收的是最终播放轨道的所有权与变形结果。

## 7. 技术约定

- 帧率 30，单位米，Y-up（导出时转换）
- 片段命名与上表 id 完全一致
- 一次性动作首尾姿态尽量接近 `idle_stand`，便于 0.25s 淡出
- 移动片段额外交付标定速度（m/s）、步长、循环周期和左右脚支撑区间。起步、停止和转向单独验证；原地循环加速度匹配本身不保证脚部锁定。
- 每个片段单独交付：GLB（或 .blend + 导出脚本）+ 预览 GIF + 轨道清单
- 版本字段：`assetVersion`、`rigVersion`、`clipVersion`、源文件 SHA-256；元数据增加 `tracks`、`blendIn/Out`、`interruptWindows`、`compatibleActions`、`validatedSpeedRange`

---

## 8. 验收标准

1. 在 V8 上播放不扭曲、不炸开（正面 / 侧面 / 背面三个视角各检查一次）
2. 轨道集合符合第 6 节的分层约定
3. 待机与移动状态下进入/退出 upper 均无跳变，移动中挥手结束不停止行走
4. 循环片段首尾无缝
5. 移动片段在候选 0.75–1.25 倍速下实测脚部世界位移；若不通过则缩小公布范围。覆盖起步、减速停止、转向，不仅测试匀速循环
6. 组合检查 walk + greet + tail_idle、notice 打断、循环边界与交叉淡出；检查领结、肩臂、裙摆、尾根和离地间距
7. 观察模式拖动与松手后均不自动移动/转身；明确退出本身不触发转身
8. Blender 求值与运行时导出采用同一姿态、坐标系、权重方案对比；记录最大误差及异常部位，避免把加载器错误误判成原模型问题
