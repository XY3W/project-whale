运行 `npm run dev -- --host 127.0.0.1 --port 5182` 后打开 `http://127.0.0.1:5182/xiangqi-assets.html`。可选动作、按秒停帧、正侧背/特写、戴盆组合、满盘搬运及导出媒体。棋盘在所有验收视角都替代旧地面网格；“满盘”按钮只切换32枚棋子和视角。

`assets/`延用已有忽略规则，本地共享制作源；运行包/方案/脚本入Git。正式棋规、状态机和执行器仍待DeepSeek接入，不能把验收页当作游戏已完成。

## 尺寸、比例、坐标

米；glTF +Y上、角色+Z前，单位外层缩放。场地/底板11.5×11.5m，棋格1.15m；`x=(col-4)*1.15, z=(row-4.5)*1.15`。row0黑、row9红。外围木边也是棋盘底板，整面覆盖场地，不叠旧16×16网格。“楚河”与“汉界”相向，汉界相对楚河旋转180°。

棋子：半径0.46m、直径0.92m、高0.2553m。半径=格宽1.15m×0.4，直径占格宽80%；最终厚度0.2553m；这是已经制作进网格的尺寸，加载时不得再乘2或再乘1.15。圆角、微凸顶面、文字一起适配。底板扩大至11.5m，避免外排棋子越出板边。底面中心为原点。14模板共享棋身/图集，32枚ID和朝向见`initial_layout.json`。

`character_xiangqi.glb`保留当前`blink-material-v2`全部网格、蒙皮、材质、节点和45旧动画，只追加16段。`motions.glb`是轻量替代包，需按清洗后的节点名重新绑定，不能复用另一场景的UUID。材质眨眼/睫毛和多权重蒙皮继续使用；不启用脸部曲面修正。

**新catalog是增量契约**，保留`/models/playful-v2/catalog.json`已有道具和动作配置再合并，不能整份替换丢掉旧能力。当前生产加载常量尚未自动切到新模型。

## 动作事件

均原地动画，实际时长/事件以catalog为准。名称保留便于接入，但`chess_pickup`语义已改为魔法吸附。

|动作|时长|事件/用途|
|---|---|---|
|stow_scoop|1.4s|0.9s waist_attach，之后空手收回|
|unstow_scoop|1.4s|0.5s hand_attach，回手持|
|chess_pickup / chess_recover|1.8s|0.4s summon_start，1.2s grasp；双手先准备，棋子再飞入|
|chess_hold|1.6s循环|双手在侧面中部夹托，前臂水平、手腕顺直|
|chess_carry_start|0.8s|前进0.045m|
|chess_carry_walk|1.6s循环|每圈0.18m，0.1125m/s|
|chess_carry_stop|0.8s|前进0.045m，仍抱持|
|chess_carry_adjust_01/02/04/06/08|各0.8s|持棋前进1/2/4/6/8cm|
|chess_place|1.8s|0.4s release，1.2s目标落稳等待提交，1.3s确认后收尾|
|chess_capture_place|1.8s|0.4s release，1.1s目标上方等待提交，成功后删除敌子，1.5s落座|
|chess_safe_setdown|1.6s|0.4s release，1.2s临时放置检查，不提交棋步|

抱棋类接管身体、双臂、头发和尾巴骨骼；不叠普通走跑摆臂、持勺/持盆层或手势。眨眼继续运行。挂勺只含右臂，保留另一手已有占用层。

平移与动作同一时钟：起步`0.045*u²`；循环`0.1125*t`；停步`0.045*(2u-u²)`；短步`distanceM*u²*(3-2u)`。倍率0.75～1.25，动作和位移同步。转向先停稳，整体角色与公共持棋锚点一起转。满盘演示一格1.15m：起步+4圈+停步+8cm×4+2cm。

## 锚点、曲线、槽位

- 地面参考点在角色前方0.85m，走近站定后才吸附；没有深蹲，也没有够地面的隐藏手臂动作。
- `prop_motion.json`为actor局部曲线，位置线性、四元数xyzw最短slerp。飞行姿态保持平稳，平滑起停。世界坐标由actor.matrixWorld组合，不能二次换轴。
- held阶段使用一个公共持棋锚点。左右手分别验证catalog的骨骼局部参考点；该指标是跟随误差，不是把控制点误差宣称为皮肤表面的几何间隙。两手不能各设一个parent。
- 抱持参考：棋子底高约0.32235m、中部掌部约0.45m；相对地面其他棋子顶约0.06705m的余量仅是参考姿势数据。
- 左右前臂解算在同一水平面，手骨方向延续前臂；不使用垂腕提沿。手与宽袖的卡通握持区域单独记录交叠，不宣称完全零接触穿插。
- `rightWaist`为`root.x`骨骼局部、列主序挂接矩阵，直接`bone.matrixWorld * binding`；沿用原右手挂点。挂腰后右手槽真正空闲，禁止从腰直接敲盆/挖掘/投掷。
- 盆可以继续戴头。手持盆先戴头、手持勺先挂腰，由LLM决定准备动作，执行器验证。

## 魔法搬运事务：接入时必须同步改变旧假设

1. 服务端授权后靠近、对正。0.4s开始飞入，源格实体一直复用同一pieceId；在1.2s真正到手才进入held。
2. 抓取后解除源格的地面障碍，逻辑源格仍由pending占用。不能留透明碰撞箱或复制棋子。
3. 到目标旁送出，**0.4s release后物体已脱手**，处于transferring。不能再要求它贴着双手下降，也不能在提交点检查“仍被双手握住”。此时检查授权、revision、目标位置和执行代际。
4. 空目标：1.2s到达地面停住等提交；确认后完成收尾。吃子：1.1s在被吃子上方停住等提交，成功删除被吃子后才继续下降。身体和曲线共用暂停时钟，不能用固定延时冒充确认。
5. 棋步只结算一次。逻辑回合与表现锁分开；落稳/收身结束后再开放下一步。拒绝或断线时保留pending和真实物体位置，不能假报成功。
6. 最高优先级事件立即撤销旧代际派发。安全清理可把棋子平稳飞落附近空地释放双手，不走完整回程。临时放置不提交棋步。恢复须走近记录的位置，再用recover吸附。
7. 旧token撤销，新任务对账后重新授权。回源格可沿平滑曲线，避免瞬移。任意行走相位抢占、断线重连和多页租约由正式执行器接入后验收。

## 验证与交付范围

`integrity.json`验证原模型/旧动画不变；`validation.json`包含时长、挂点、前臂倾角/手腕方向、接续与脚步；`geometry-validation.json`记录采样姿势、初始32子接近与几何路线；`carry-footprint.json`包含角色/尾巴/腰勺的低位投影，不能只按脚的圆形导航。

几何检查为采样顶点/截面与低位轮廓检查，不能代替全部面片相交、布料模拟或正式寻路。接入后仍需测密集后续局面、真实ACK、装备槽位、用户弧线、棋规逐例、闹钟抢占和重连。用户已确认最新比例、河界文字方向并要求进入开发；正式场景中的搬运、密集棋局与异常打断仍待接入后验收。

复现顺序：`build_textures.py` → Blender `build_board.py` → `build_assets.py` → `bake_actions.py` → `package_runtime.py` → Node `validate_runtime.mjs` / `check_runtime_geometry.mjs` → `finalize_delivery.py`。Blender使用`-b --python-exit-code 1 --python`。所有输入在共享Mac，读取.blend时禁用脚本。

棋身/木纹/棋盘自行制作；字面由未修改的思源黑体栅格化，附OFL和来源。原角色、既有盆/勺沿用原授权；没有重新授权角色。
