## 改了什么

旧版先指定手的位置、再解肘部，同时独立指定手腕朝向；固定的肘部弯曲方向不能适应姿势，造成收缩、折向和运动重心不自然。旧版勺头移动也过小。

新版重新制作 `knock_basin_prepare`、`knock_basin_hit`、`knock_basin_finish`。敲击采用肩部主导的 FK：固定肩点，旋转上臂带动前臂、手和勺；肘部沿骨架局部 X 轴自然屈曲，前臂转向在准备阶段完成，正式敲击时不再改变肘部和手腕的局部姿势。身体比例、臂长、模型网格、蒙皮权重、物品几何及原挂接矩阵保持不变。

| 实测指标，单个敲击循环 | v1 | v2 |
| --- | --- | --- |
| 上臂相对起始姿势的最大旋转 | 15.57° | 32.00° |
| 肘部弯曲范围 | 53.57–69.26° | 约 35°，敲击中保持稳定 |
| 肘局部旋转变化 | 17.92° | 0° |
| 腕局部旋转变化 | 5.08° | 0° |
| 勺头一次往返路程 | 约 4.16 cm | 约 38.16 cm |
| 肩点位移 | 0 | 0 |

前臂持勺转向为固定 75°，在准备阶段平滑进入，收回阶段回到既有持勺姿态。它是制作好的动作参数，不是开放给 LLM 的骨骼控制入口。敲击轨迹避开脸部、头发和裙摆，接触盆背部金属表面。

反向持盆的三个片段沿用 v1：`hold_basin_outward`、`basin_grip_outward`、`basin_grip_inward`。原有 39 片段全部保留，运行包仍为 45 片段、83 骨。

## DeepSeek 如何接入

1. 使用本包 `runtime/character_playful.glb`、`catalog.json`、`tracks.json` 和全部音频文件/音频目录替换相应资产；新版本号为 `playful-interaction-v2`，不要把 v1 和 v2 的同名片段同时追加到动画库。
2. **必须同时更新 catalog 的敲击 effectPoint**：新接触点在勺体上的位置已重新计算，不能继续使用 v1 的点。
3. ID、时长、事件协议不变：准备 0.7 s；每次 hit 0.6 s、片段内 0.24 s 触发 `knock_contact`；收回 0.7 s。一次或四次总长分别为 2.0 s、3.8 s；四下接触时刻为 0.94、1.54、2.14、2.74 s。
4. 敲盆时由片段接管双臂，不能再让左右持物 hold 覆盖活动手臂。下身/呼吸/尾巴仍按原框架分层。起止姿势已匹配，避免在接触帧跨淡入淡出。
5. 左盆、右勺仍沿用原手骨绑定矩阵。不要额外应用预览 guide 的世界变换，否则会双重变换。GLB 里的原多权重属性保持不变，继续使用已实现的权重加载链。
6. 一次敲击只由实际事件播放一次音效，物理碰撞回调不能重复播放同一次主动敲击；使用实例 ID＋击打序号去重。取消、租约和工具权限沿用原方案，不在此次资产修订中放宽。

`prop_motion.json`、盆 GLB、直杆木柄金属勺 GLB 与上游保持一致。新能力草案依旧默认 disabled，待应用侧修复及运行验收后由 DeepSeek 启用；这不是要求 DeepSeek 重新制作动作。

## 音频

12 个文件仍使用相同文件名：敲击、落地拟音、侧面碰撞拟音各 4 段。WAV PCM16、单声道、48 kHz，样本峰值约 −6 dBFS，未检出削波采样。

音色改为真实录音剪辑与混合，未使用旧版程序化共振振荡器。来源是 Anthousai 的金属碗敲击/台面接触和 chonkdonk 的手持金属锅敲击，均为 CC0。确切链接、下载文件哈希、切片区间和处理方式见 [AUDIO_LICENSES.md](../assets/playful-interaction-v2/AUDIO_LICENSES.md)、`audio_sources/SOURCES.json`、`runtime/audio_catalog.json`。

来源限制如实保留：敲击原录音使用木勺敲金属碗/锅；落地与碰撞音为金属碗台面接触拟音，并非本模型钢盆被投掷的精确实录。下载的是公开 HQ MP3 预览，转换成 WAV 不恢复原 WAV 的质量。四个敲击变体共享金属碗共鸣，但使用四个不同的手持锅敲击片段，不能描述为四次独立录制的本模型敲击。

反弹仍由物理系统决定，每个接触事件选择一次音效，不在一个音频里预先叠一串固定反弹。增益随碰撞强度变化，保留原方案中的休眠过滤、去抖、用户解锁 AudioContext 和静音规则。运行音量需在服务器页面中试听校准。
