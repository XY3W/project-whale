# 跑动、双手物品与扫雷：下一批实现方案

2026-10-26 · Codex 负责方案、建模、动画；DeepSeek 负责服务器应用代码与接入。

状态：方案与资产已本地交付，应用代码待 DeepSeek 实现；本文件不是服务器功能完成声明。此前 [今日计划](DAY_PLAN_2026-10-26.md) 的执行权、取消、事件账本、恢复与 Key 处理事项继续有效，不能被小游戏覆盖。服务器核对基线：`810ebf4`，本地仅制作资产与文档。

## 1. 已确认的新需求

- 长距离可以跑，步长比走路大；微调位置仍然走。LLM 决定目的、距离、朝向与走/跑选择，播放器只执行和校验。
- 左上角按钮文字固定为「扫雷开局」，启动 10×10 棋盘；棋盘出现、揭示更新和完成都会触发 LLM 思考。
- 角色右手持饭勺向前作一次挖掘；必须走到目标格，动作接触时才揭示数字或雷。挖到雷即失败。
- 饭勺可拾取、投掷、右手持有；不可戴头或装备到身体其他部位。
- 盆迁移为左手持有，仍可戴头、取下、拾取和投掷。两手可以同时持物。

用户已于 2026-10-26 正式确认首版规则：15 颗雷、首次挖掘格安全、数字按周围八格计算、零格展开、挖开所有非雷格获胜。首次安全只保护本格，不宣称必然可无猜通关。当前采用 10×10、15 雷，不再列为待确认项。

## 2. 场地与游戏规则

当前 Stage 实际是 8m × 8m、16×16 装饰网格；扫雷时替换为 10×10，仍占 8m × 8m，每格 0.8m，不另建不对齐的叠加小网格。非扫雷模式沿用原场地。

统一坐标：Three.js +Y 上、+Z 角色朝前。col 从 -X 向 +X，row 从 -Z 向 +Z；整数 0..9。格心 `x=-4+(col+0.5)*0.8`，`z=-4+(row+0.5)*0.8`。计算 cell 使用半开区间，+4 不属于棋盘，不能 clamp 成最后一格。移动仍遵守角色/物品对墙净空；边缘格按面向棋盘内部的站位可达性验证，禁止为了到格心穿墙。

格子可以悬停显示坐标，但点击格子不触发移动或挖掘，保持所有角色行为由 LLM 下令的既定规则。走过未揭示格不爆炸；只有成功提交 dig_contact 才挖开。视觉显示未揭示、0..8、雷、已爆雷和胜负状态。数字与角色/物品投影区分，禁止改高度导致角色绊住。格面仅做渲染，不为每格创建动态刚体。

第一次 dig_contact 提交时，服务器生成并持久化雷区，排除本格；不能每次刷新重新布雷。种子、雷表、未揭示格邻雷数仅存在服务器私有状态；前端、LLM、日志提示词、客户端 debug 快照都不得收到它们。失败后可公开展示所有雷，游戏终止后 LLM 不再挖。

零格展开视为一次原子揭示：返回同一 revision 下的 changedCells，至多 100 格；只触发一次场地更新，不能每展开一格都调用一次模型。首版不做插旗、撤销和连点开邻格。LLM 可在任务记忆保存推断，不将推断写成权威雷表。

胜负：挖到雷 status=lost；非雷已开数量=100-mineCount 时 status=won。重复挖同一格返回 ALREADY_REVEALED，不扣次数、不再次播动作、不触发新模型循环。

按钮在游戏中显示「重新开局」可作为状态文案，但原始入口文字为「扫雷开局」。重复点击通过 requestId 幂等处理；重新开局换 gameId、revision 清零，取消旧棋盘计划并等角色安全收势，不在投掷/转移提交点中途强行重置物品。新局不能复制饭勺、重置盆、清空聊天或修改角色身体。

## 3. 跑动接口与位移

`walk(distance_m)` 保留现有精确微调职责，新增 `run(distance_m)`，不让 LLM 调原始关节、骨长或动画 timeScale。

机械随机漫游也可在足够长且前方净空充足的直线段选跑动（建议至少 0.784m），短段仍走路；它仍是最低优先级，触发 LLM/聊天就停止。命令执行期间不得擅自把 LLM 选定的 walk 改成 run。

跑动用专门的 run_start / run / run_stop 及配套根位移曲线。参数和最短可完成距离以交付 catalog 为准；不得沿用 walk 的步幅计算。初始只允许直线跑；转向必须先停稳，再显式 turn(angleDeg)。场景快照同时给出走/跑已验证速度、最小执行距离、可用距离和估计时长。

预期基础跑速约为旧走速的 3–4 倍。完整步周期与位移同步缩放，不允许只把角色世界速度加快而脚步没变。首版 LLM 不直接调速度倍率，固定 1×；作者候选倍率范围留给接入验收后开放。一次 run 先执行可容纳的完整起步、循环、收步，剩余距离通过显式 walk / walk_adjust 计划完成；walk_adjust 为已制作的 0.02/0.04/0.06/0.08m 短步，0.8 秒一次，最后至多 0.01m 的量化误差仍须满足目标站位和接触容差；执行器不能自作主张增加目标距离或超跑后倒退。能力校验拒绝短于起收步距离或不满足量化步长的 run，并返回可执行距离与残差供 LLM 重新规划。

正常停止可收步；用户聊天、租约失效、预算耗尽或急停必须立即禁止继续世界位移，结束余下动作只为安全外观，不能借收步越过边界或继续执行下一格。安全停止优先于脚步连续。

## 4. 物品、双手与动作资源

世界数据升级时只初始化一把饭勺（固定 object_id=rice_scoop），选择场地内可用的初始落点，记录已创建标志并持久化。再次开局、刷新或短暂物品消息缺失不能再生成一把；每局开局只重置棋盘。

用通用 ObjectRegistry 描述 `objectId/type/state/holder/transform/revision/affordances`，不可再把单个 BasinProp 当作全局唯一物品。盆 holder 可为 left_hand 或 head，饭勺仅 right_hand。一个槽最多一个物品；一次物品最多一个所有者。物品数量不因加载、拾取或断线增加。

用户已确认饭勺拾取为脚尖轻挑、右手接住：走到饭勺旁，toe_lift 前饭勺保持地面静止；之后由受控抛接轨迹接到右手。它有真实的起点、连续轨迹和提交点，不是远程吸附。此动作当前验证平躺勺面朝上或朝下；不支持的落地姿态返回原因，不悄悄扶正。

动作命名沿用盆的 pickup_basin / hold_basin / throw_basin / wear_basin / unwear_basin，但新资产中 hand binding 为 hand.l，必须整体更新 catalog、prop_motion、tracks、模型版本。禁止仅把右手盆节点改挂左手，仍播放旧右臂动画。

饭勺新增 pickup_scoop / hold_scoop / throw_scoop / dig。拾取、手持和投掷在非扫雷模式也可用，只有 dig 依赖正在进行的棋盘。实际时刻、挂点矩阵、参考姿态和轨道 mask 见资产交付；方案不猜矩阵。拾取统一遵守先走近、停稳、对齐、接触时复检。任意倾倒姿态不等于资产已支持；支持范围必须从资产测试报告读取。不允许自动扶正、吸到手上再播放拾取。

分层：空手臂用 base；左手持盆只覆盖左臂轨道；右手持勺只覆盖右臂轨道。主动动作接管使用的手，另一手保持其 hold 层；全身蹲起与当前活动手协调。运行时必须测「盆左手+饭勺右手」的 idle、walk、run、dig，以及单手拾取/投掷、戴盆/取盆。佩戴盆只影响头部挂点和既有头顶形态键，不影响饭勺状态。

投掷事件从实际该手挂点取得位置与姿态，交给物理。物品碰撞体、质量、惯量、反弹和休眠参数分类型；饭勺不能复用盆半径。release 之后动画不得覆盖物理位置或在 clip end 强写 flying。刚体反弹只影响物品，不替用户增加角色碰撞伤害等新规则。

旧存档盆 holder=hand 在迁移事务中映射为 left_hand，并使用新挂点重建持物姿态；旧 transferring、执行中动画不得从右手时间轴中间切到左手。先冻结为 unknown，按旧账本确定持有或地面状态后再升级。版本不符时暂停动作并明确报错，禁止混装。

## 5. LLM 能力与公开快照

新增/更新能力：

| 能力 | 参数 | 必要校验 |
|---|---|---|
| run | distance_m | 资产允许距离/倍率，直线段、边界、执行权、无冲突动作 |
| walk / walk_adjust / turn | distance_m / angle_deg | 用于格心与拾取站位的最后对齐 |
| pickup_scoop | object_id | 地面静止、右手空闲、支持姿态、已对齐、接触误差达标 |
| throw_scoop | object_id、angle_deg、elevation_deg、speed_mps、spin_rps | 右手正持此物；范围不超过已验证投掷包络 |
| dig | game_id、row、col、expected_revision | 游戏进行中、目标未开、角色在该格、站稳、右手有饭勺 |
| 既有盆操作 | object_id 及既有参数 | 改成左手；wear 仅盆可调用，unwear 要求左手空 |

禁止给 LLM `setCell`、`revealAll`、`spawnItem`、任意位置拾取、跳过动画提交或直接写状态的工具。LLM 选择哪格、走/跑多远、转多少度，执行器负责校验。首版不加入暗中规划路线的 move_to_cell 宏；快照给目标格心与当前位姿，LLM 显式组合 turn/run/walk/dig。原 walk_to_basin 宏的路径决策边界仍按今日计划审查。

公开快照必须有：snapshotId、timestamp、gameId、revision、status、10×10公开 cell 数组、雷总数、已开安全格数、remainingSafeCells、lastReveal、坐标公式；角色 position/yaw/forward/currentCell/速度/活动通道；每个物品的位置、状态、holder、支持操作与实际拾取姿态；双手槽；动作范围；当前预算与原始用户目标。

未揭示格只发 `{row,col,state:'hidden'}`，不能发隐藏 value、危险色、内置概率或雷相关邻接数据。LLM 可根据已见数字推理，不靠私有答案作弊。

## 6. 挖掘结算与事件循环

1. 接受 dig 时记录 actionInstanceId、gameId、expectedRevision，验证已到目标格并静止。首版站位要求根位置在格心 0.12m 内；实际勺头投影也必须在同格安全内边距内。朝向偏差按资产样例测试确定，不能直接套头部朝向。
2. 播放 dig；在 catalog 的 dig_contact 时刻再次验证租约/代际、同一局同一 revision、目标未揭示、站位未变、右手同一饭勺。
3. 服务端根据可信的执行器事件、幂等账本和权威状态原子提交揭示。可编辑客户端消息不能直接决定结果；服务器复算坐标和状态，不信任客户端传来的数字/雷值。
4. 取消在提交点前发生：没有揭示；提交后发生：保留已经揭示结果并安全收势，不撤销结果再重挖。
5. 事件至少带 gameId、revision、sourceActionId、changedCells、status。`game_started`、`board_updated`、`game_finished` 都是高优先级模型思考触发原因。
6. 每次揭示改变决策信息，当前计划中尚未开始的后续挖掘和移动停在安全边界；用最新快照重新思考。不能让 LLM 一次返回 30 个 dig 然后闭眼顺序播放。
7. 同一次成功挖掘既有 plan_result 又有 board_updated：合并到同一轮 review，并将事件标记已消费。最后一格/踩雷的 board_updated 与 game_finished 同样合并，一次调用同时处理两种原因，仍满足两种事件均被考虑。
8. 思考/执行中收到外部事件：去重并暂存最高 revision，安全中断旧计划，再处理；游戏事件不能绕过当前聊天的用户指令优先级。达到单轮预算后保持任务暂停，不能靠新 revision 重置预算变成无限 API 循环。

未执行用户命令时仍保留最低优先级随机漫游；活跃扫雷任务期间不随机踩走站位。游戏停滞、模型判断需猜测或用户转移话题时可以先回应用户，等待下一指令，不自动开新局。模型失败保留真实棋盘和物品状态，显示既有断连红图标，不继续无人监管挖掘。

提示词完整新增段落与 JSON 示例随资产交付提供，必须加载到真实 planning 和 review，而非只写在说明文档里。

## 7. 先修基础，再接功能

顺序：修今日计划 P0/执行权/取消/唯一任务ID/原子恢复 → 接双手物品与新资产 → 接跑动位移及停止 → 纯规则扫雷 → 动作事件结算 → LLM 公开快照与事件合并 → 端到端浏览器验收。

一开始可以用本地假模型/纯规则测试并行开发游戏，不必调用真实 Key。不得因新增小游戏推迟仍会重复执行/租约失效后继续动/重启丢物的已确认问题。

必须覆盖：首次挖掘安全与布雷一次、八邻数字、零展开一次事件、胜负及重复 dig、越界与错误 gameId/revision、未到格/无勺/右手物品错误、掉帧跨接触点、接触前后取消、双客户端争用、重载恢复、完局事件合并、模型失败不继续、旧存档左右手迁移、双手跑动挖掘无穿插、投掷后再拾取支持边界。最后用真实浏览器验证 UI 按钮/10×10可读性/聊天仍可用/头顶思考状态；测试和构建通过不能替代视觉确认。


接口命名适配：上文状态快照可沿用项目已有 camelCase 字段；LLM 工具参数必须沿用当前 snake_case（distance_m、angle_deg、object_id 等），不可让提示词与校验器各用一套命名。资产 action ID 与工具 ID 分离，例如 run 工具内部组合 run_start/run/run_stop，walk_adjust 按 distance_m 选短步片段；盆现有 pickup/throw/wear/unwear 工具可保留，通过 object_id 映射正确物品与左手动画，不强制改所有旧工具 ID。

点击角色进入聊天时，正在执行的扫雷行为同样走统一安全取消和事件提交规则；不允许小游戏私建一个不受聊天、租约或预算控制的循环。既有任务预算必须在游戏 UI 中显示，预算用尽暂停并由用户明确继续，不能用新棋盘 revision 自动重置预算。首版不承诺一次开局在任意配置下都能自动扫完整盘。
