## 2. 已发现的主要缺口

| 位置 | 问题 | 修复方向 |
|---|---|---|
| BrainClient / server | 服务端用 session_state 发阶段，客户端不消费其中 phase | 统一有版本的状态协议 |
| main / ActionExecutor | 漫游与模型计划独立调用同一执行器 | 单一 Coordinator 管理所有动作来源 |
| main.waitFor / ActionExecutor | 超时正常 resolve，随后标成功，stopped 固定 true | 类型化结果、真实终止与停止证据 |
| server.fail / canRoam | 错误结束任务为 idle，漫游不检查连接和错误 | 挂起错误状态和显式恢复 |
| server lease | 新连接直接接管，页面全部非只读 | 真正执行端租约及 fencing token |
| server / protocol | 结果缺少 planId，旧异步错误可结束新任务 | 完整 ID、代际与执行账本 |
| llm.validate | 类型强转、距离四舍五入，约束多处手写 | 共用注册表和严格 Schema |
| ChatPanel | IME、后台超时、重试及记忆 UI 不完整 | 明确输入事件与恢复流程 |
| context / storage | 短内存历史，无最小记忆与完整世界快照 | 持久化和有预算的上下文组装 |

## 3. P0-A：先统一控制权和任务状态

### 3.1 模块职责

保留现有动画播放器、场景和 UI；逐步从 main.ts 抽取以下职责，不进行无关框架迁移：

- `Coordinator`：浏览器唯一动作调度入口；决定停止、接管、执行、恢复漫游。
- `ActionExecutor`：只执行获准计划，返回真实结果；不自行恢复漫游。
- `TaskSession`：服务端任务状态、模型请求、轮次预算、结果和重试管理。
- `CapabilityRegistry`：能力、参数、通道、时长与校验来源，前后端共用。
- `SnapshotProvider`：由当前实际状态采样，禁止拿计划终点充当当前位置。
- `ContextBuilder` / `SessionStore`：后续阶段加入上下文和持久化。

服务端负责任务阶段的权威状态；浏览器负责身体阶段及本地停止。消息包含 sessionId、taskId、revision，客户端忽略过期 revision。统一使用一种状态广播，避免 session_state/task_state 两条路径各自维护不同事实。

分别保存 chat、task、motion、controlOwner、network、lease 状态，不用一个 busy 布尔值兼任全部职责。任务至少有 none、thinking、executing、checking、cancelling、error、blocked、unknown。

只有 Coordinator 可以启动或恢复漫游，且同时满足：聊天关闭、无活动或待处理任务、无错误/unknown/blocked、连接正常、持有有效租约、身体安全停稳、无其他动作所有者。动画结束、聊天关闭、重连成功都只能发事件，不能直接开启漫游。

### 3.2 点击角色和新消息

点击角色：停止接纳漫游步骤，取消漫游剩余部分，安全收步；保存点击时相机位置，停稳后据实际角色位置计算面向角度，以最短路径转身，然后打开聊天框。opening 期间重复点击合并，不重复排队。点击本身不调用 LLM。

点击发生在 LLM 任务中也走统一取消流程；取得当前部分结果后结束旧任务，进入聊天，不能让旧计划继续后台运行。

新消息：生成新的任务代际，撤销旧计划未开始步骤；当前动作安全终止并取得实际快照后再规划新任务。取消可能需要收步，不能瞬间冻结。输入进入待处理状态即可立即显示头顶“思考中”，身体停稳后再播放 think。

一次最多一个执行中的计划。漫游、聊天入场转身和 LLM 计划都通过同一入口，不允许分别 executor.run。每次运行有独立取消信号；禁止新 run 重置一个全局 cancelled 布尔值而复活旧计划。

### 3.3 该阶段验收

- 漫游转向中、走路中、收步中点击角色，各重复测试：只收尾一次，不再开始旧漫游后续步骤。
- 计划执行中连续发送新消息：旧计划后续步骤不执行，最新任务不被旧响应覆盖。
- 任务未结束时关闭聊天或两分钟超时：任务仍按当前规则继续，漫游不抢占；完成且检查结束后才有资格恢复。
- 聊天开着时任务结束：保持聊天待机，不漫游。

## 4. P0-B：动作结果必须真实

底层 walk/turn/play/tail/wait 返回结构化终止结果，至少区分 succeeded、cancelled、failed、unknown；不再用 Promise<void> 表示一切正常。等待超时返回 TIMEOUT，并请求停止；停止也超时则报告 unknown/stopped=false，阻止继续执行或恢复漫游。

每步记录 requested、actual、start/end snapshot、起止时间、状态和 reasonCode。计划 stopped 由实际身体与活动通道判断，不能固定 true。取消时保留已经完成与部分执行结果，后续步骤标 cancelled，不把整个计划假装成完全未执行。

具体规则：

- walk：根据起步、循环数、收步和播放速率估计时长，加明确余量；不能统一使用 15 秒。完成时核对真实位移、方向和运动状态。初始验收阈值：距离误差 ≤1 mm、转角误差 ≤0.5°；若资产或采样无法满足，报告测量结果，不擅自放宽或调整请求目标。
- turn：取消后不继续转到旧目标；记录累计有符号角度，避免 -180° 被归一化成 +180°。角度归一化可用于显示朝向，不能用来证明转动方向。
- play：单次动作等到通道实际结束；循环 think 由宿主状态驱动并明确退出。如果作为工具暴露，必须采用带有限 duration_s 的已批准 Schema。
- tail/wait：定时等待可取消，取消后清理旧计时器，不能让旧回调关闭新任务的摆尾。
- parallel：先整组校验通道冲突和参数；运行中一个子动作失败，取消其余子动作并收集结果，之后才允许重试或新计划。
- 实际位置越界时安全限制并报告阻挡/偏差，不能 clamp 后仍回报请求距离成功。

验收覆盖全部 11 个距离值，特别是 1.71m、1.89m；0.5m 和 0.449m 必须被拒绝，不得取整为 0.45m。模拟底层不运动但正常返回、长时间不结束、取消时部分移动等情况，执行器均不能报成功。

## 5. P0-C：错误、重试、租约和去重

### 5.1 错误与重试

API 超时、鉴权、限流、网络、非法输出、执行异常进入持久的 error/blocked 状态，保留任务、阶段和执行账本；安全停稳、头顶红色断连图标、聊天中具体错误及重试按钮。不能调用通用 endTask 抹掉任务再恢复漫游。

WebSocket 可做有上限退避的连接重试；连接恢复不等于任务恢复。没有新鲜状态和对账结果前不能清除错误并漫游。模型请求不做无限自动重试。

重试分开处理：

- planning 失败：重新采样后重试规划。
- review 失败：重新采样并带原执行账本，只重试检查，不重播旧计划。
- 执行部分失败：记录部分结果交给 review；新计划只处理必要剩余部分。
- unknown：先对账；证据不足时保持阻塞，不推断成功、不自动重放。

无 API Key 的生产模式报 NO_KEY。FakeBrain 仅通过显式开发开关启用，并在界面和诊断中标识；不能生产环境静默降级成关键字脚本。

所有异步成功和失败处理都校验 taskId、generation、requestId。过期请求的成功、异常、超时均只能记诊断，不能更改新任务。取消旧请求时同时 abort 网络请求，但不能只依赖 abort 来防竞态。请求超时覆盖响应体读取，不只等待响应头。

### 5.2 协议与租约

服务端生成稳定的 sessionId/taskId/planId/stepId/requestId，结果携带对应标识及 turnId、generation、leaseEpoch、capabilityVersion。未知、过期或不属于当前执行端的结果拒绝进入任务状态机。步骤 ID 在任务内唯一，不能每轮都从无命名空间的 s1 开始。

租约采用持有者、单调递增 epoch、到期时间和心跳续租。建议心跳 5 秒、到期 20 秒；有效持有者不被新页面抢占。所有执行、快照更新、结果提交校验当前租约，其他页面只读。执行端本地租约过期立即停机；服务端失联后标 unknown，对账完成前不能向新端重发未明动作。旧页面重新联网必须重新获取权威状态，不能沿用旧 epoch。

执行前持久记录计划已派发，浏览器接收时记录已接受；完成后保存结果。重复完成结果按 planId 返回既有确认；重复派发的已完成计划返回缓存结果而不再次执行。刷新或崩溃导致证据不完整时保持 unknown，不能宣称跨崩溃绝对 exactly-once。

每任务最多 4 个执行计划；第 4 个执行完仍必须允许一次 review 来结束或解释，不能在检查前截断。180 秒预算由主动计时器检查，不能只在收到结果时检查。预算超限进入 blocked 并安全停止，不能悄悄变为 idle。

## 6. P1-A：统一能力、提示词和现场上下文

按本地 llm-design 已写正文接入，不能另写一个弱化的 review 提示词。提示词版本和 capabilityVersion 可诊断。使用一个注册表生成模型能力说明及 Schema，并供服务端和执行端校验。

严格检查 JSON 类型、必填、enum、范围、additionalProperties、最大步骤数、parallel 不嵌套和通道冲突；不做 Number/string 强转、静默截断时长或四舍五入距离。完整计划通过静态校验后才下发，每步执行前还要复查动态边界与前置条件。

每轮 planning/review 都采样完整当前快照，至少包含版本、时间、有效性、场地边界/障碍、位置、朝向/forward、运动和通道状态、聊天/控制状态、物品/事件、能力版本和剩余预算。review 同时带原始用户目标、所有相关已完成/部分失败结果，不能只给最后一轮并丢掉前面的位移。

服务端持久位置不能覆盖刚执行完的实际坐标。使用执行结果快照推进版本，必要时主动请求浏览器新快照；连接断开、状态过期或仍在收步时暂停规划，禁止使用示例坐标补值。

物品与事件先实现数据协议及测试夹具：stable id、revision、位置、affordances、关注事件 ID 和去重。当前空场景返回真实空集合。pickup/carry/push/use 等以 disabled 能力及原因提供给 LLM，不注册为可执行工具；不需要为验收凭空新增生产场景物品。没有用户输入或实际关注事件时不调用 LLM。

## 7. P1-B：持久化、上下文预算和最小记忆

遵循 CONTEXT_MEMORY.md，推荐 SQLite 存储 sessions/messages/tasks/plans/step_results/memories，运行数据加入 gitignore，迁移保留已有位置文件数据。单角色执行租约与聊天 ownerScope 分离：旁观或新浏览器不能自动获得其他会话的聊天、偏好。

- 会话历史持久化；两分钟退出不清空。保留策略默认 30 天，但未完成任务及对账证据不提前清理。
- 输入目标预算 8000 tokens、输出预留 2000 tokens，并受实际模型上限约束；无准确 tokenizer 时保守估计，记录估算方式。
- 优先保留系统规则、当前目标、当前快照、执行失败/unknown 和已完成证据；再保留相关已确认偏好、最近最多 12 轮对话和有来源摘要。关键内容仍超限则明确报错，不静默削弱限制。
- 最小记忆只含明确称呼、语言/回复风格和普通兴趣；模型提案是 candidate，服务端校验来源与白名单。普通偏好需用户确认；明确“记住/以后叫我”等按原契约验证后处理。模型不能自己写 confirmed。
- 聊天增加记忆查看、确认、删除及清空会话入口。删除同时清除相关衍生摘要/检索缓存，后续不能从旧历史自动复活。
- 记忆提案非法时独立拒绝，不让合法动作重试或重复执行；不新增后台记忆提取调用。

## 8. P1-C：聊天与显示细节

- 头顶 thinking/checking 显示“思考中”；停稳后播放 think，执行计划或结束时退出该通道。执行中显示执行状态，不能一直叫思考中。
- 中文 IME composing 时 Enter 不提交；输入事件与键盘事件可以续时，鼠标点击发送、相机拖动、模型回复不能续两分钟。
- 处理活动事件之前先检查旧 deadline 是否已过期；后台恢复不能用第一下键盘把已超时会话复活。草稿仍保留。
- 新消息允许按既定抢占流程提交，按钮与 Enter 行为一致，不出现按钮禁用但 Enter 可提交的两套规则。
- 服务端维护聊天打开状态，并拒绝 closed 状态发来的 user_message；不只信任客户端 UI 隐藏。
- 红色图标由 error/unknown 状态驱动；单纯 WebSocket open 不能清除模型错误。重试入口在检查失败时明确标记“重新检查”。

## 9. 提交顺序与验收矩阵

按下列批次提交，每批附测试与未完成事项，不将全部修改堆成一个无法定位问题的大提交：

1. A：统一状态协议、Coordinator、取消与漫游门禁。
2. B：真实动作结果、超时/停止、所有距离和有符号角度。
3. C：任务代际、持久执行账本、租约、错误重试、重连对账。
4. D：能力注册表、提示词、世界快照与场景事件协议。
5. E：历史/记忆、上下文预算、聊天边界和验收交付。

账本存储接口在 C 引入，E 扩展历史与记忆，避免 C 先写一套临时存储再推翻。

| 验收场景 | 必须结果 |
|---|---|
| 点击正在漫游的角色 | 停止旧计划，收步后面向用户，聊天开启 |
| 请求全部合法距离与 ±180° | 测量达标，方向正确，最长动作不提前结束 |
| 请求 0.5、0.449、字符串数字、嵌套并行 | 严格拒绝，无动作副作用 |
| 动画卡住或执行未达到目标 | 失败/unknown，有真实 actual，绝不假成功 |
| thinking/executing/checking 时关闭聊天 | 活动任务不被漫游抢占 |
| 连续用户输入、旧响应/旧异常晚到 | 旧结果不修改新任务，旧步骤不复活 |
| 401/429/超时/非法 JSON/无 Key | 明确错误、红图标、停止漫游、可重试 |
| review 失败后重试 | 不重复任何已完成动作 |
| 重复派发和重复结果 | 同一 plan 不执行两遍 |
| 双页面、刷新、失联、服务重启 | 单执行端，旧 epoch 无效，未知任务先对账 |
| 第 4 轮完成、180 秒超时 | 前者仍检查，后者主动安全停止并 blocked |
| 当前与历史位置冲突 | 以新鲜现场状态为准 |
| 记忆候选、确认、删除、重启和其他会话 | 权限及来源正确，不丢失、不复活、不串会话 |
| 长历史超预算 | 保留目标与执行证据，或明确拒绝；不重复动作 |
| IME Enter、后台超过 2 分钟 | 不误发、不续活已过期聊天，草稿保留 |

测试分层：纯逻辑单测；使用可控模型适配器的 WebSocket/任务集成测试；真实浏览器与真实动画的端到端测试；最后少量真实 DeepSeek 冒烟验证。故障注入走测试适配器，不修改生产 Key 或故意消耗 API 配额。不能用模拟 loco 的测试通过来替代动画实测。

## 10. 部署与交付要求

开发验证使用独立测试进程和端口，不连接生产 SQLite、不占用生产执行租约。完整构建及测试通过后再替换线上产物、重启服务；保留上一版本可回滚。不要边构建边覆盖服务正在使用的 dist。

交付本地 `docs/LLM_FIX_DELIVERY.md`，包含：基线与最终提交、逐批完成清单、测试命令及结果、真实动画位移/角度/时长数据、故障与双页面验收结果、真实 API 是否验证、配置项名称（不含密钥）、数据迁移/回滚方法、仍未完成和已知限制。

不得只写“M1–M5 完成”。分别标明已编码、自动测试通过、浏览器实测、真实 API 实测、已部署；未实测项目明确写未实测。
