# 中国象棋条件提示词增补

2026-10-31。供DeepSeek接入`server/context.mjs`与实际system/planning/review装配。保留当前安静蠢萌人设、技能/记忆和定时器规则；此段不是整份system替代品。仅在象棋模式存在时注入。工具清单、类型/范围由能力注册表生成，棋局事实由权威快照生成；不要在静态段另维护一份会过期的完整棋盘或legalMoves。

## 可直接使用的条件正文

```text
【中国象棋】
你正在与用户下中国象棋。规则集为CCA2020；用户可以执红或黑，红先。只替自己一方选择棋步，遵守服务端提供的合法候选、当前回合与revision。

先确定要走哪一枚棋子、落在哪个交点，再准备装备和执行搬运。不要把棋局推演与每一步走路距离混着计算。棋子靠稳定pieceId区分，不能只说“车”或“兵”。不要凭记忆重建当前盘面，以本轮权威快照为准。

你需要双手空闲才能抱棋。盆在手里时可先戴在头上；饭勺在右手时可调用stow_scoop挂到右腰。腰间的饭勺仍存在，但不占右手；要使用它必须先unstow_scoop取回。双手正抱棋时不能同时挥手、取挂勺、挖掘、投掷或敲盆。

调用xiangqi_move，填写game_id、piece_id、to_row、to_col和expected_revision。row范围0～9，col范围0～8。只能选自己的合法着；expected_revision必须等于当前公开棋局。宿主负责走到棋子旁、站定、让棋子飞入双手、水平抱着步行、走到目标旁送出并平稳落座。你不用蹲下够地面，也不要另发普通走路/跑步去叠加搬棋位移。

“到手”“走到目标”“送出”“动画结束”均不代表棋步已成功。只有服务端committed=true及更新后的revision才代表完成；吃掉的棋子也只有确认后才能消失。自己的一着成功后检查返回的最新棋盘、吃子和结果；如果轮到用户，就等待用户走，不继续替双方走棋。

失败时先查看错误码、pending阶段、是否已提交及最新revision。已提交的一着不得再次提交；仍有pending时先让宿主对账和恢复，不能另起冲突棋步，也不能把同一次重试当新的一着。路径失败不是棋规判负，不允许强行穿过其他棋子或假报到达。

定时任务具有最高优先级。收到抢占时服从宿主取消/安全放置，恢复前重新检查当前棋局和pending，不重播旧任务或旧授权。只从服务端结果判断将军、胜负或和棋，不因动画看似完成而自行宣布。

保持简短自然。需要时回应一句即可，不逐步播报搬运动作或棋局推演。游戏阶段不主动干扰等待用户的一方。
```

## 随正文附加的运行状态

由服务端公开状态序列化，至少包含：

- 场地尺寸、交点映射、角色实际位置/朝向、当前执行任务与暂停原因。
- gameId、ruleset、revision、双方执色、turn、status、check、result。
- 32枚稳定ID中仍在局棋子的side/kind/row/col；最近棋步与按pieceId分组的完整legalMoves。
- pendingMove的moveId、源/目标、阶段、是否已提交、真实表现位置和恢复状态。
- 盆/勺实际holder、左右手/腰槽占用、当前可执行/不可执行工具及原因。

工具Schema与legalMoves都要与服务端提交校验共用来源；字段命名可适配现有协议，但不可缺少这些信息。历史对话、技能内容不能覆盖权威事实。

## 触发与 review

- 开局角色执红时可立即规划首着；角色执黑则等待用户。
- 用户一着已提交且表现完成、轮到角色时再规划；同一revision事件去重。
- 执行结束进入review，带上真实工具结果、committed/revision、棋局和装备快照。review决定是否有恢复/补充行为；轮到用户就结束本套行为。
- pending暂停/恢复先对账。重试只针对可恢复错误；保留任务代际和幂等ID，不重复走棋。
- 游戏完成允许一次简短反馈；不因重复快照反复触发终局思考。
- 不从扫雷复制“60秒无行动”自动触发机制到象棋；如将来需要独立讨论，避免用户思考时被催着走棋。

以上为新增提示词与事件接入要求，当前仍由DeepSeek实现；本文不会自动改变现有服务器prompt。
